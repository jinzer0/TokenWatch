# Purpose

Desktop code is the Electron and React preview for TokenWatch's sanitized usage analytics. It reads normalized SQLite metadata through the main process and shows read-only analytics without exposing prompts, responses, credentials, raw paths, raw session IDs, raw records, SQL payloads, stack traces, or arbitrary metadata dumps.

# Key files

- `main.ts` owns Electron window creation and points the app at the packaged preload bundle.
- `main/` owns main-process database lifecycle, service wiring, and IPC handlers.
- `preload.ts` exposes the typed `window.tokenwatch` API to the renderer.
- `shared/` owns sanitized IPC channel names, schemas, DTO contracts, and shared desktop types.
- `renderer/` owns the React UI and must stay browser-only.

# Local rules

- Desktop first release is read-only analytics. Scan and import management remain CLI/TUI scope unless a task explicitly changes that product decision.
- Keep the renderer behind the preload boundary. Desktop renderer code must not import `electron`, `node:*`, `better-sqlite3`, `src/db`, or `src/services`. It should use only typed preload methods.
- Keep IPC narrow and typed. Preload should expose specific `window.tokenwatch` methods, not generic send, invoke, subscribe, or listener passthroughs.
- Keep DTOs sanitized before they cross into preload or renderer code. IPC payloads, logs, screenshots, UI text, fixtures, and evidence must not include prompts, responses, credentials, raw paths, raw session IDs, raw records, SQL payloads, stack traces, or arbitrary metadata dumps.
- Keep Electron security defaults intentional: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, and packaged preload path `../preload/preload.cjs`.
- Keep main-process DB and service imports out of preload and renderer code. Main process may use service and DB modules, preload may expose typed methods, and renderer may consume only the preload API plus shared browser-safe types.
- Keep desktop packaging outputs generated. `out/` is generated by `corepack pnpm build:desktop`, and `release/` is generated by `corepack pnpm package:mac`. Don't hand-edit either directory.
- Don't document or capture signing account names, signing identity details, notarization secrets, passwords, machine-local paths, or any viewer for unsanitized prompt/response content.

# Tests/verification

- For desktop source changes, run the closest `corepack pnpm test:desktop` target, then `corepack pnpm typecheck`.
- For main, preload, native module, or packaging changes, add `corepack pnpm build:desktop` and `corepack pnpm package:mac` when scope requires packaged verification.
- When behavior touches desktop app launch, IPC, DB lifecycle, renderer privacy, or packaging, perform a real desktop smoke check with `TOKENWATCH_DB_PATH=/tmp/...` and verify captured logs don't contain preload, native-module, or privacy leaks.
- After `corepack pnpm package:mac`, verify Node-side `better-sqlite3` still loads before trusting later Vitest runs.
- For documentation-only desktop guidance changes, run `corepack pnpm format:check AGENTS.md src/desktop/AGENTS.md` when Markdown formatting is in scope.

# Pitfalls

- Don't add scan/import controls to desktop unless the task explicitly changes the read-only first-release scope.
- Don't route around preload by importing Electron, Node, DB, or service modules in renderer code.
- Don't add broad IPC helpers that expose raw `ipcRenderer`, generic channels, or unbounded event listeners.
- Don't turn missing prices into `$0.00`; keep unknown prices as `null` or `unknown`.
- Don't use real user databases in desktop smoke checks. Set `TOKENWATCH_DB_PATH` to a temp path.
