## 목적

PR #23 게시 후 Codex의 두 P1에 대해 로컬 수정·검증을 수행했다. multi-bucket/null ID 및 GUI형 PATH/절대 경로 override를 수정했고 전체854/desktop190·타입/lint/build·합성 subprocess smoke가 통과했다. 이후 리뷰 수정의 커밋·기존 게시 브랜치 푸시를 명시 승인받았다. 새 공증 패키지는 수행하지 않았으며 상세 결과는 Stage5/최종 보고의 리뷰 대응 절을 따른다.

요청자의 `좋아 다음으로 일단 못하는 건 생략`에 따라 현재 불가능한 검증은 사실상 미검증으로 남겨 이번 진행에서 보류한다. 그 재시도는 다음 단계의 선행 조건이 아니다. 이후 커밋·푸시·PR는 명시 승인받았고 병합·이슈 종료는 별도 승인 경계를 유지한다.

승인된 UX 설계를 독립된 데스크톱 프로그램처럼 일체감 있는 Electron 앱으로 구현한다. 처음 열었을 때 Claude·ChatGPT Codex·Cursor의 구독 잔여량과 리셋, 사용 여유를 먼저 파악하고 일간·주간 로컬 토큰 통계로 맥락을 확인하도록 한다.

Graphite·Paper·Slate를 동일 기능의 선택 가능한 테마로 제공한다. Graphite를 최초 기본값으로 사용하고 앱 설정에서 바꾼 테마를 재실행 후에도 유지한다.

## 배경

- 사용자 지적: 타이틀바와 본문의 단절감, 전체적인 웹 페이지 인상. 특정 OS 디자인 모방이 아니라 데스크톱 도구다운 통합된 경험이 목표다.
- TokenTracker에서 채택한 참고는 대시보드 정보 배치다. 메뉴바 기능·캐릭터·투명도를 복제하지 않는다.
- [DESIGN.md](../../_bmad-output/initiative-desktop-ux-ui-refactor/ux-desktop-ux-ui-refactor/DESIGN.md)와 [EXPERIENCE.md](../../_bmad-output/initiative-desktop-ux-ui-refactor/ux-desktop-ux-ui-refactor/EXPERIENCE.md)가 시각·행동의 근거다. `draft / provisional` 상태이며 명시 승인과 잠정 기본값을 구분한다.
- 현재 `Shell.tsx`에는 큰 소개 영역과 개인정보 설명 배너가 있고, `DashboardContent.tsx`에는 다수 분석·진단 패널이 한 화면에 구성되어 있다.
- `DesktopDashboardService`는 SQLite 로컬 이벤트를 집계한다. 현재 IPC의 getSnapshot과 refresh는 둘 다 DB 대시보드 재조회이므로 새로고침만으로 구독 실시간 수집이 되는 것은 아니다.
- 기존 `providerUsage.ts`는 OpenAI·Anthropic API models 엔드포인트 탐지이며 구독 quota 연동 구현이 아니다. Cursor 구독 연동도 완료되었다고 간주하지 않는다.
- 선행 이슈 #9·#10·#11·#12·#13·#19의 데스크톱 변경과 보안·검증 규칙을 유지한다.

- 실제 화면·키보드·포커스·대비·작은 창·네이티브 모듈·격리 DB 검증.

- 실제 계정 접근이나 인증자료 조회를 계획 작성 승인으로 자동 허용하는 것.

- 30일 이전 데이터 삭제·보존 정책 변경. 30일은 계산에 사용하는 입력 상한이다.

- 기존 상세 분석·진단 기능의 승인 없는 삭제. 첫 화면 밖 이동이 필요하면 기존 접근 경로와 회귀 검증을 계획에 반영한다.

## 설계 방향

### 구현 경계

- 데이터 수집과 수학 계산은 services, 정규화 보관은 repositories, IPC DTO는 desktop/shared, 렌더링은 renderer에 둔다. 기존 의존성 주입·Zod 스키마·검증된 설정 저장 패턴을 우선 사용한다.
- 현재 desktop DB lifecycle은 읽기 전용이다. 테마 저장을 위해 사용량 DB를 쓰기 모드로 전환하지 않고, main 소유의 제한된 화면 설정 저장소와 typed IPC를 상세 계획에 정의한다. DB 미설정 상태에서도 테마 선택이 가능해야 한다.
- renderer는 브라우저 전용이며 Node·DB·자격증명에 접근하지 않는다. main의 권한 있는 송신자 검증과 preload의 좁은 typed API를 유지한다.
- `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, 패키지 preload 경로를 유지한다. 창 드래그 영역과 클릭 영역을 분리한다.
- 데이터가 최신인지 원본 관측 시각으로 판단한다. 화면 생성 시각을 원본 수집 시각처럼 표시하지 않는다.
- 기존 로컬 보고·내보내기·CLI/TUI 동작을 보존한다. 구독 데이터는 기존 usage event에 임의 원본 메타데이터를 섞는 방식으로 추가하지 않는다.

### 확정 동작

- 화면 문구는 `주간 60% 남음`, `20% 여유`, `10% 부족`처럼 간결하게 한다. 가상 한도 단위·수학식·면책성 문장은 앱 화면과 툴팁에서 제거하되 보안·미확인 처리 규칙은 유지한다.
- 남은 사용량 비율과 다음 리셋까지 필요량 대비 여유율은 별개 항목이다. D>0일 때 `(R-D)/D×100`, D=0이면 상태 문구를 쓴다.
- SES 입력은 최근 7~30일 자료다. 7일 미만은 `사용 이력 부족`이며 전망 비율·소진 시각을 숨긴다. 30일 초과 이력은 남겨두고 계산에서만 제외한다.
- 누락 구간을 0 사용으로 채우지 않는다. 미확인 잔여량을 0으로 바꾸지 않고 미확인 가격은 null/unknown으로 남긴다.
- 기본 Graphite, Paper·Slate 동등 지원. 설정에서 변경하고 재실행 시 마지막 저장 성공 값을 유지한다. 테마 변경은 서비스·기간 선택과 수집 상태를 초기화하지 않는다.

### 잠정 기본값 및 구현 전 검증

- 시스템 시간대, 오늘·월요일 시작 이번 주, 어제·지난주의 같은 경과 구간 비교. DST·시간대 변경을 테스트한다.
- 보이는 창에서 60초 간격, 수동 갱신, 창 복귀 시 한 번 갱신. API 정책과 실제 수집 지원을 확인한 뒤 확정한다.
- 테마 즉시 적용·저장, OS 테마 자동 연동 없음. 저장 실패는 짧은 오류와 다시 저장 동작으로 알린다.
- α·초기 수준·집계 구간·유효 관측일 완전성은 Stage 1에서 확정할 기술 판단이다. 7일이라는 표시 조건을 정확도 보장으로 해석하지 않는다.
- 최신 30일 이력이 모두 오래된 경우나 리셋 경과 후 갱신이 없을 때 현재 전망을 만들어내지 않는다.

## 잠정 구현 단계

### Stage 1 — 데이터 가용성 및 계약 확정

- 공개 문서·기존 코드·합성 샘플로 Claude/Codex/Cursor별 구독 데이터의 권위 있는 수집 경로와 정책을 확인한다. 실제 계정 접근은 별도 승인된 방법만 사용한다.
- 접근에 필요한 인증 처리, 공유 한도·주기·리셋·원본 시각·증분 산출·저장 최소 필드·최신성 기준을 결정한다.
- SES α·초기화·구간 및 관측 완전성, rolling 평가 방법을 정한다. 단순 평균보다 우수하다는 결과를 미리 주장하지 않는다.
