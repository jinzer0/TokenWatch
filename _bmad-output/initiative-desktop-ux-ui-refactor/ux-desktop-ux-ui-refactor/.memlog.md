- (decision) 사용자가 확정한 요구: 대상은 Electron 데스크톱 앱. 특정 OS 네이티브 스타일 모방이 아니라 독립된 데스크톱 프로그램이라는 인상을 원한다. 창과 타이틀바의 단절감 및 전체적인 웹 같은 시각 인상을 개선한다. 앱 실행 첫 화면은 토큰 사용량 대시보드이며 현재 구독 플랜의 실시간 사용량, 주간·일간 사용량 등 간략 통계를 보여준다. 문서 위치는 현재 작업 폴더로 승인되었으며 앱 소스 구현은 별도 승인 대상이다. 구독 데이터 출처·한도 정의·실시간 갱신 주기는 아직 미확정이다. 상위 initiative의 .memlog.md에는 원본 대화 결정 기록이 있다.
- (decision) ユーザーが指定した対象サービスは Claude、ChatGPT Codex、Cursor。ユーザーは最初の画面に追加する価値がある指標の調査と提案を依頼した。候補の採用や具体的な視覚デザインはまだ確定していない。
- (override) 앞선 서비스 범위 기록의 한국어 정본: 사용자가 지정한 지원 대상은 Claude, ChatGPT Codex, Cursor다. 첫 화면 대시보드에 추가할 지표를 조사하고 제안하되, 후보 채택과 시각 디자인은 미확정이다.
- (event) 조사 결과: 현재 데스크톱에는 로컬 토큰 집계, 추세 비교, 모델·소스별 집계, 세션 요약, 가격·예산 진단이 있다. renderer 훅은 초기 조회와 명시적 새로고침만 수행하며 자동 실시간 구독 갱신을 확인하지 못했다. providerUsage 서비스는 OpenAI·Anthropic API 키 기반 models 엔드포인트 탐지이고 quota는 unknown이다. 구독 플랜의 권위 있는 잔여 사용량 수집이 구현되었다고 볼 수 없다. 공식 문서는 서비스별 사용량 단위와 공유 범위가 다름을 보여주므로 로컬 토큰 합계로 구독 사용률을 추정하면 안 된다. 조사 세부 근거와 미확정 후보는 .working/dashboard-research.md에 보관한다.
- (decision) 사용자가 첫 화면 대시보드에 추가할 항목을 확정했다: 남은 사용량과 리셋 시각, 어제·지난주 대비 증감, 서비스별 사용 비중, 짧은 사용량 추이, 과거 사용 속도 기반 고갈 전망과 부족·충분 비율. 고갈 전망의 기준 기간과 부족·충분 비율의 분모는 아직 미확정이다. 구독 전망은 서비스가 제공하는 한도와 동일한 단위의 사용 이력이 있어야 하며 로컬 토큰 합계로 구독 한도를 추정하지 않는다. 전망은 실측값과 분리해 추정임을 명시한다.
- (decision) 사용자가 고갈 전망의 부족·여유 비율을 다음 리셋까지 예상 필요량 대비로 정의했다. 예상 필요량 D, 현재 잔여량 R에 대해 D>0일 때 (R-D)/D×100을 사용한다. 양수는 여유, 음수는 절댓값으로 부족, 0은 예상 필요량과 동일함을 뜻한다. 이는 잔여 한도 퍼센트가 아니라 예상 필요량 대비 차이다. D=0이면 비율과 예상 소진 시각을 산출하지 않으며 관측된 사용 없음과 이력 부족을 구분한다. 서비스별 한도와 동일한 단위, 유효한 리셋 시각 및 충분한 관측 이력이 없는 경우 예측 불가로 표시한다. 과거 사용 속도를 산출할 관측 기간과 최소 이력 기준은 아직 미확정이다.
- (change) 사용자는 대시보드에 예측값이라는 직접적인 라벨을 표시하지 않도록 요청했다. 필요량 0일 때는 숫자 비율 대신 적절한 상태 문구를 원한다. 과거 사용 속도 입력 기간은 약 2주로 정하고, 단순 평균에 고정하지 말고 수학적 예측식과 정확도 검증 방법을 조사하도록 요청했다. 실제 남은 사용량·리셋과 모델 기반 전망을 혼동시키지 않도록 대체 문구와 상세 설명 방식은 설계에서 제안한다. 사용 이력 누락은 0 사용과 구분한다.
- (event) 예측 문헌 조사 완료: 단순 지수평활, 계절 단순법, 평균법과 rolling-origin 검증을 조사했다. 최근 14일 이력으로 서비스별 후보를 비교하되 리셋까지 누적 수요 오차를 검증하도록 제안한다. 실제 데이터 성능 검증은 미수행이다. 예측값 라벨 대신 현재 추세 기준 문구, 0 수요는 최근 사용 없음 등 조건별 문구를 제안했다. 세부 근거와 경계 조건은 .working/forecast-research.md에 저장했다. 후보 방식과 문구는 아직 사용자 확인 전이다.
- (override) 사용자가 고갈 전망 방법과 관측 기간을 최종 선택했다: 단순 지수평활을 적용한다. 유효한 관측 이력이 7일 미만이면 사용 이력 부족으로 표시하고 전망 수치와 소진 시각은 숨긴다. 7일 이상부터 계산 결과를 표시하되 잔여량·리셋·동일 단위 등 기존 데이터 전제도 충족해야 한다. 사용할 과거 이력은 최근 최대 30일이며, 종전 약 14일 고정 입력과 여러 모델 자동 선택 제안을 대체한다. 모델은 지수평활로 고정하고 평활 계수 산정·검증은 별도 기술 결정으로 남긴다. 수집 공백은 무사용 0으로 채우거나 유효 관측일로 간주하지 않는다. 기존 UX 요청인 예측값 라벨 미표시와 필요량 0의 조건별 상태 문구, 다음 리셋까지 예상 필요량 대비 여유·부족률 정의는 유지한다. 7일이면 높은 정확도가 보장된다는 의미가 아니다.
- (change) 사용자가 최대 30일의 의미를 명확히 했다: 데이터 저장·보존 기간의 상한이 아니라 지수평활 계산에 투입하는 과거 데이터 범위다. 계산 시 최근 7~30일 데이터를 사용하고, 유효 이력이 7일 미만이면 사용 이력 부족으로 표시한다. 30일을 넘는 과거 데이터의 삭제나 보존 정책 변경은 요청하지 않았다. 종전 최대 이력 표현은 계산 입력 기간 상한으로 해석한다.

- (change) 사용자는 승인된 정보 배치는 유지하되 새 시각 스타일 시안을 요청했다. 앱 화면에서 보장 아님, 잔여 한도 퍼센트 아님, 미확인을 잔여량 0으로 표시하지 않음 등 면책성 설명을 모두 제거한다. 서비스 구독 영역의 60 단위 같은 가상 단위 표현을 없애고 주간 60% 남음, 10% 여유, 10% 부족처럼 퍼센트 중심으로 표시한다. 측정 잔여 비율과 필요량 대비 여유·부족 비율의 계산 정의는 내부 설계에서 유지하며 미확인은 숫자 0으로 바꾸지 않는다. 상태 문구는 사용 이력 부족, 확인 필요처럼 짧게 한다. 시안의 예시 데이터 표시는 앱 밖 검토용 캡션으로 분리한다. 지수평활 계산은 최근 7~30일 입력과 최소 7일 조건을 유지한다. 새 시각 스타일은 비교 시안으로 제시하며 아직 최종 선택되지 않았다.
