# TokenWatch Desktop — Experience Spine

## Foundation

Electron 데스크톱의 대시보드·선택 서비스 상세·화면 설정을 다룬다. [최신 결정](.memlog.md)에 따른 **작성 완료된 잠정 초안**이며 최종 종료나 구현 승인이 아니다. 개인 개발자 중심 맥락은 잠정 가정이지 사용자가 공개한 신원이 아니다.

Claude·ChatGPT Codex·Cursor가 대상이다. 사용자는 지금 더 사용할 수 있는지 먼저 판단하고 로컬 통계로 맥락을 확인한다. 확인된 잔여량과 모델 기반 사용 여유를 다른 항목에 두며 계산 설명은 이 계약에만 남긴다.

시각 규칙은 [DESIGN.md](DESIGN.md)를 따른다. Graphite 기본, Paper·Slate 동등 지원, 설정에서 선택·재실행 후 유지가 확정이다. 즉시 적용·OS 자동 연동 없음과 아래 기간/갱신/접근성 상세는 잠정 기본값이다.

## Information Architecture

| Surface          | Reached from                      | 목적과 구성                                                                                             |
| ---------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 대시보드         | 앱 실행·화면 설정에서 돌아가기    | 상단 AppToolbar, 왼쪽 PeriodSummary·UsageTrend, 오른쪽 주 ServiceUsage, 아래 ServiceShare·ServiceDetail |
| 선택 서비스 상세 | ServiceUsage 선택                 | 대시보드 안 ServiceDetail만 변경; 선택 서비스의 남은 사용량·리셋·여유·소진 전망·별도 로컬 집계          |
| 화면 설정        | AppToolbar의 `설정` → `화면 설정` | AppearanceSettings 안 ThemeChoice와 저장 상태; 돌아가면 이전 서비스·기간·스크롤 보존                    |

별도 메뉴바·트레이 표면이나 추가 분석 기능은 이번 계약에 넣지 않는다. 서비스 순서는 Claude → ChatGPT Codex → Cursor; 최초 선택 Claude는 시안에 따른 잠정 기본값이다.

### Data contract

아래는 내부 정의이며 화면 설명문이 아니다. [대시보드 조사](.working/dashboard-research.md)와 [전망 조사](.working/forecast-research.md)의 세부 근거는 복제하지 않는다.

| 항목             | 의미와 표시 조건                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 남은 사용량      | 서비스가 권위 있게 제공한 잔여 비율 또는 같은 사용량 풀의 유효한 잔여량 R / 한도 L × 100(L>0). 주기명과 `% 남음` 표시     |
| 사용 여유        | 다음 리셋까지 예상 필요량 D>0일 때 `(R-D)/D×100`; 양수는 여유, 음수는 절댓값으로 부족, 0은 `필요량과 동일`                |
| 소진 전망        | 누적 미래 사용량이 R에 처음 도달하는 시각; 리셋 전에 도달하지 않으면 `리셋까지 여유`. 임의로 리셋 이후 시각을 만들지 않음 |
| 로컬 토큰        | 허용된 로컬 집계의 토큰 합계; 구독 소비량·API rate limit과 별개이며 구독 잔여량의 대체 입력이 아님                        |
| 서비스 사용 비중 | 선택한 로컬 집계 기간의 서비스별 토큰 / 같은 범위의 전체 토큰. 분모 0이면 비율 미표시; 수집 불완전이면 부분 집계로 구별   |
| 비용             | 이번 핵심 화면의 우선 항목 아님. 이후 상세에 노출하더라도 미확인 가격은 `null`/`unknown` 유지, `$0.00`으로 치환 금지      |

동시에 여러 한도가 있으면 서비스·사용량 풀·주기별로 구분한다. 서비스 간 잔여 비율을 합치지 않으며 대표 한도를 임의 선정하지 않는다. 모델 제공자와 실제 사용 서비스를 혼동하지 않는다.

### Forecast rules

- 방식은 **단순 지수평활(SES)** 고정: `l_t = αy_t + (1−α)l_(t−1)`. α·초기 수준·집계 bucket 단위는 구현 전 기술 검증 항목이며 여기서 고정 알고리즘을 새로 정하지 않는다.
- 입력은 최근 최대 30일 중 유효 관측 이력 최소 7일이다. 7일 미만이면 `사용 이력 부족`, 전망 비율·소진 시각 모두 숨김. **30일은 계산 INPUT 상한이지 보존·삭제 정책이 아니다.**
- 7일 이상이어도 같은 단위의 이력·잔여량·유효한 다음 리셋이 필요하다. 누락 구간은 0이나 유효 관측일로 세지 않는다. 관측일 완전성·허용 공백·부분 구간 처리는 데이터 검증 후 결정한다.
- 미래 구간 수요를 리셋까지 누적해 D를 계산한다. 불완전한 구간을 완전한 관측처럼 학습하지 않는다. 반올림 전 값으로 상태를 판정하며 표시 정밀도로 부호를 뒤집지 않는다.
- D=0이면 비율·소진 시각을 산출하지 않는다. 충분히 관측된 무사용이면 `최근 사용 없음`, R 상태는 별도 유지한다. 관측 이력에 사용이 있는데 D=0이면 `사용 추세 확인 필요`다.
- R=0이 확인되면 `0% 남음`; D>0이면 부족 계산을 유지하되 이미 소진된 상태에 미래 소진 시각을 꾸며내지 않는다. R 미확인은 `확인 필요`이지 0이 아니다.
- 리셋이 지났는데 새 한도가 없으면 `리셋 후 갱신 대기`; 이전 주기의 잔여량으로 새 전망을 계속 계산하지 않는다.
- 주기 카운터 리셋, 추가 구매·플랜 변경, 한도 차단에 따른 관측 수요 억제는 기술 검증 대상이다. 잔여량 감소를 사용량 증가와 무조건 같다고 보지 않는다.
- 정확도 검증은 미래 정보 누수 없는 rolling-origin, 같은 서비스·단위·리셋 구간의 누적 오차/과소 산출 편향을 평가하는 제안이다. α 선택·평가 구간 수는 미확정이며 7일이 정확도 보장은 아니다.

### Calendar and refresh — provisional

- 날짜는 시스템 시간대, 일간은 오늘, 주간은 월요일 시작 이번 주다. 비교는 어제·지난주의 **같은 경과 구간**으로 맞춘다. 일광절약시간·시간대 변경 시 경계 처리와 집계 정합성은 구현 전 검증한다.
- 비교 기준값이 0이면 증감 절대량은 표시할 수 있지만 증감률은 `비교 기준 없음`; 현재값도 0이면 무사용 상태다. 누락된 이전 기간은 `비교 정보 없음`으로 구별한다.
- 짧은 추이는 최근 7일을 쓸 수 있으나 달력 주간 요약과 구별해 기간을 표시한다. 서비스 비중·상세 로컬 합계는 선택한 오늘/이번 주 범위를 공유한다. 테마 변경은 기간을 초기화하지 않는다.
- 리셋은 서비스가 제공한 시각을 우선하고 화면에서 시스템 시간대로 변환한다. 달력 주간과 구독 리셋 주기를 같다고 가정하지 않는다.
- 보이는 창에서 **60초 간격**, 수동 새로고침, 창 복귀 시 한 번 갱신이 잠정 정책이다. 중복 요청은 합치고 숨긴 창의 주기 조회는 멈춘다. 수집 지원·서비스 정책을 먼저 검증한다.
- 새로고침 완료 시각과 원본 관측 시각은 별개다. 최신성은 원본 기준으로 판단한다. 수집 지연/실패나 만료된 리셋이 있으면 `마지막 확인` 또는 갱신 대기 상태를 유지한다.
- 서비스별 지연 허용 기준은 기술 미확정이다. 확인 전에는 `실시간`·현재 연결 상태를 보장하지 않으며 재조회만으로 오래된 데이터를 최신으로 승격하지 않는다.

## Voice and Tone

짧은 한국어 항목명과 행동을 사용한다. 아래 숫자는 문구 예시이지 실제 데이터가 아니다.

| 상황            | 앱 문구                                              | 계약상 주의                                     |
| --------------- | ---------------------------------------------------- | ----------------------------------------------- |
| 구독 잔여       | `주간 60% 남음`, `리셋 · 내일 09:00`                 | 검증된 주기·수치·시각만 치환                    |
| 사용 여유       | `20% 여유`, `10% 부족`, `필요량과 동일`              | `예측값` 직접 라벨 없이 남은 사용량과 구획 분리 |
| 관측 없음/부족  | `최근 사용 없음` / `사용 이력 부족`                  | 무사용과 미관측을 구별                          |
| 미확인          | `확인 필요`                                          | 숫자를 만들지 않고 해당 항목만 제한             |
| 오래됨/오프라인 | `마지막 확인 · 09:00`, `오프라인`                    | 원본 시각이 없으면 시각도 꾸며내지 않음         |
| 일반 실패/권한  | `불러오지 못했어요` + `다시 시도` / `접근 권한 확인` | 내부 오류·자격증명·원본 경로 노출 금지          |
| 테마 저장 실패  | `테마를 저장하지 못했어요` + `다시 저장`             | 성공 확인 전 `저장됨` 금지                      |

가상 한도 단위·수학식·긴 기술 설명·면책 문장을 화면이나 툴팁에 넣지 않는다. 모델 기반 항목은 `사용 여유`와 `소진 전망`이라는 항목명으로 실측 잔여량과 구별한다.

## Component Patterns

모든 시각 토큰은 [DESIGN.md](DESIGN.md)에서 해석한다. 테마별 표면 매핑과 {typography.body.fontSize}, {typography.meta.fontSize}를 공유한다.

| Component          | 사용처와 행동                                                                                                                                      |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| AppToolbar         | 새로고침은 중복 방지, 진행 상태만 갱신하고 포커스 보존. 설정 진입점을 제공하며 {components.AppToolbar.minHeight}와 OS 예약 영역 유지               |
| PeriodSummary      | 오늘/이번 주 값과 같은 경과 구간 비교. 기간 선택은 로컬 비중·상세 범위에만 반영하고 구독 주기를 바꾸지 않음                                        |
| UsageTrend         | 결측은 끊어 표시; 0은 실제 0 높이. 키보드/텍스트로도 날짜별 값과 누락을 확인 가능, {components.UsageTrend.labelSize} 사용                          |
| ServiceUsage       | 클릭·Enter·Space로 서비스 선택; `선택됨`과 접근성 선택 상태 갱신, ServiceDetail만 교체. 서비스별 실패는 다른 서비스에 전파하지 않음                |
| ServiceShare       | 서비스명·수치·집계 범위 제공. 장식 그래프만으로 읽기를 강제하지 않으며 부분 집계를 전체로 표시하지 않음                                            |
| ServiceDetail      | 선택 서비스와 같은 데이터 snapshot/원본 시각을 사용. 전환 중 이전 서비스 값을 새 이름 아래 재사용하지 않음; {components.ServiceDetail.rowGap} 유지 |
| AppearanceSettings | 화면 설정의 돌아가기/Escape로 대시보드 복귀, 이전 설정 진입점에 포커스 복원. 데이터 수집 실패와 관계없이 접근 가능                                 |
| ThemeChoice        | 이름이 있는 단일선택 그룹; 선택 즉시 적용하고 로컬 저장 요청. {components.ThemeChoice.minHitSize} 이상, 선택 서비스·기간 보존                      |
| StatusMessage      | 국소 상태와 필요한 재시도만 표시; {components.StatusMessage.fontSize}. 새 오류/완료는 정중한 알림, 반복 60초 갱신마다 낭독하지 않음                |

## State Patterns

| State                        | Surface                   | 처리                                                                                                                                                |
| ---------------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cold load                    | 대시보드                  | 저장된 테마를 읽고 정보 자리 유지, `불러오는 중`. 관측 전 숫자 0이나 합성 값 금지                                                                   |
| Loading                      | 대시보드·선택 서비스 상세 | 기존 값이 있으면 원본 시각과 보존; 진행 중 동작의 중복 실행만 제한, 다른 서비스 선택·설정은 유지                                                    |
| Empty / zero                 | 대시보드·선택 서비스 상세 | 수집 완료된 0이면 실제 0 표시. 첫 관측 전이면 `사용 이력 부족`. 비중 분모 0은 숫자 비율·막대 없이 무사용 상태                                       |
| Missing                      | 대시보드·선택 서비스 상세 | 누락 항목은 `확인 필요`; 이력 부족이면 전망 숨김. 한도 미확인이 로컬 집계를 지우지 않음                                                             |
| Offline                      | 대시보드·선택 서비스 상세 | 마지막 성공 상태와 `오프라인`·원본 시각 표시; 이력이 없으면 조회 불가 상태. 새 전망을 현재값처럼 생성하지 않음                                      |
| Stale                        | 대시보드·선택 서비스 상세 | `마지막 확인`으로 기존 상태만 제공; 현재 소진 판단을 갱신한 척하지 않음. 리셋 경과 시 옛 비율·전망을 현재 영역에서 숨김                             |
| Access denied                | 대시보드·선택 서비스 상세 | 해당 서비스에 `접근 권한 확인`; 무한 재시도 금지. 권한 철회로 접근 불가한 데이터는 캐시로 우회 표시하지 않음                                        |
| Error                        | 대시보드·선택 서비스 상세 | 해당 영역에 `불러오지 못했어요`와 `다시 시도`; 허용된 마지막 상태가 있으면 시각을 붙여 유지                                                         |
| Cold load / empty preference | 화면 설정                 | 설정 읽기 중 선택을 확정하지 않음. 저장값이 없는 최초 실행은 Graphite; 읽기 실패는 `설정을 불러오지 못했어요`와 재시도, Graphite 임시 적용임을 구별 |
| Saving                       | 화면 설정                 | 화면은 즉시 새 테마, 저장은 `저장 중`. 마지막 사용자 선택과 저장 결과가 일치해야 완료 처리                                                          |
| Save error / access denied   | 화면 설정                 | 현재 실행의 선택은 유지, 저장 실패와 `다시 저장` 표시. 재실행 유지 대상은 마지막 저장 성공 값; 성공으로 묵인하지 않음                               |
| Offline / stale              | 화면 설정                 | 로컬 설정이므로 네트워크 상태와 무관하게 선택·저장 가능; 데이터의 마지막 확인 상태는 테마 변경 후에도 유지                                          |
| Focus                        | 모든 표면                 | 선택과 포커스를 별도로 표시. 자동 갱신·테마 변경·국소 오류가 포커스를 빼앗지 않음                                                                   |

화면 설정에는 사용량 0/이력 부족 상태를 만들지 않는다. 테마 저장 여부와 데이터 최신성은 서로 다른 상태다.

## Interaction Primitives

- `Tab`/`Shift+Tab`은 보이는 읽기 순서의 조작점 이동, `Enter`/`Space`는 선택·행동 실행이다. 표준 단일선택 그룹의 방향키로 ThemeChoice를 바꾼다.
- `Escape`는 화면 설정에서 대시보드로 돌아가고 진입점에 포커스를 돌린다. 즉시 적용한 테마를 취소하지 않는다. 대시보드에서는 앱 종료나 선택 해제로 쓰지 않는다.
- ServiceUsage를 선택해도 포커스는 선택 버튼에 남는다. ServiceDetail 갱신은 서비스명을 짧게 알리고 다음 탐색에서 상세에 접근할 수 있게 한다.
- OS 타이틀바의 빈 드래그 영역만 창 이동에 사용한다. 버튼·링크·선택 요소·창 제어는 interactive/no-drag hit region으로 분리하고 이벤트가 드래그에 먹히지 않게 한다.
- OS 닫기/최소화/최대화와 시스템 키 동작은 보존한다. 커스텀 단축키나 드래그 재정렬을 이번 범위에서 추가하지 않는다.
- 테마 적용·설정 저장은 새로고침이나 재수집을 유발하지 않는다. 저장 실패 중 빠른 재선택도 마지막 선택을 기준으로 처리하며 늦게 온 응답이 덮어쓰지 않게 한다.

## Accessibility Floor

- WCAG 2.2 AA를 목표로 한다. DESIGN의 대비 목표를 실제 세 테마에서 별도 검증해야 하며 현재 통과를 주장하지 않는다.
- 모든 버튼에 이름·역할, ThemeChoice에 선택 상태, ServiceUsage에 선택 서비스 상태를 제공한다. 차트는 동일한 텍스트 값/요약으로 읽을 수 있게 한다.
- 포커스 표시는 각 테마 accent 계열({colors.graphite-accent}, {colors.paper-accent}, {colors.slate-accent})을 실제 배경과 검증하고 선택 강조선과 구별한다.
- 글자 확대·창 축소에서도 짧은 상태와 행동을 숨기지 않는다. 키보드만으로 세 Key Flows를 끝낼 수 있어야 한다.
- reduced motion에서는 전환·차트 보간·로딩 shimmer를 제거하고 정적인 진행 상태를 쓴다. 색상 변화만으로 저장/오류/부족을 전달하지 않는다.
- 설정 복귀 시 포커스 복원, 자동 갱신 시 읽기 위치 보존, 오류 발생 시 정중한 알림을 기본으로 한다. 포커스 trap이나 hover 전용 행동을 만들지 않는다.

## Responsive & Platform

넓은 창은 승인된 좌측 보조·우측 주 배치다. 좁아지면 ServiceUsage를 먼저 보존하고 보조 영역·하단 상세를 쌓는다. 정보나 기능을 테마/창 폭에 따라 삭제하지 않는다. 정확한 breakpoint·최소 창 크기·OS titlebar hit test는 구현 검증 항목이다.

시안의 가로 스크롤 검토 컨테이너는 제품 응답형 동작의 검증 증거가 아니다. 화면 설정도 작은 창에서 스크롤 가능하며 돌아가기·저장 실패 행동은 접근 가능해야 한다.

## Inspiration & Anti-patterns

[TokenTracker 참고 기록](imports/tokentracker-reference.md)에서 채택한 것은 요약·추이·비중·상세의 정보 배치다. 거대한 누적 토큰 수, 비용 중심 화면, 메뉴바 패널·투명도·캐릭터는 채택하지 않는다. 새 의존성이나 특정 UI 라이브러리 승계도 전제하지 않는다.

## Key Flows

주인공 **가상 개발자 민서**는 흐름 설명용 허구 인물이다. 개인 개발자 맥락은 잠정이며 실제 사용자의 직업·습관·데이터를 의미하지 않는다.

### Flow 1 — 대시보드에서 남은 사용량 판단

1. 민서가 앱을 연다. 저장한 테마 또는 최초 기본 Graphite로 대시보드가 열린다.
2. ServiceUsage의 서비스별 남은 비율과 리셋, 별도 사용 여유를 확인한다.
3. PeriodSummary의 오늘/이번 주 및 이전 같은 경과 구간 증감, UsageTrend, ServiceShare로 사용 맥락을 확인한다.
4. **Climax:** 확인 가능한 잔여량·부족 상태를 바탕으로 계속 사용할 서비스를 선택한다. 수집 시각도 함께 읽는다.

**Failure:** 새 데이터가 없거나 오프라인이면 마지막 확인 상태만 읽고 필요 시 새로고침한다. 미확인 수치로 계속 사용 가능하다고 결론 내리도록 유도하지 않는다.

### Flow 2 — 선택 서비스 상세 확인

1. 민서가 ServiceUsage에서 ChatGPT Codex를 클릭하거나 키보드로 선택한다.
2. ServiceDetail이 같은 서비스·snapshot의 리셋·여유·소진 전망과 별도 로컬 합계를 보여준다.
3. **Climax:** 부족 여부와 리셋 전 소진 시점을 구별하고 다음 작업에 사용할 서비스를 판단한다.

**Failure:** 유효 이력이 7일 미만이면 `사용 이력 부족`, 한도·리셋 미확인이면 `확인 필요`로 전망을 숨긴다. 권한 오류는 해당 서비스에만 표시하며 다른 서비스로 이동할 수 있다.

### Flow 3 — 테마 선택 후 다시 열기

1. 민서가 AppToolbar의 설정에서 화면 설정에 들어가 Paper 또는 Slate를 선택한다.
2. 즉시 테마가 바뀌고 저장 성공이 확인된다. 선택 서비스·기간은 유지된다.
3. 돌아가기/Escape로 복귀한 뒤 앱을 닫고 다시 연다.
4. **Climax:** 마지막 저장 성공 테마로 대시보드가 열려 별도 선택이 필요 없다.

**Failure:** 저장 실패면 현재 화면의 선택과 저장되지 않았음을 구별하고 `다시 저장`을 제공한다. 실패한 선택의 재실행 유지나 `저장됨`을 약속하지 않는다.

## Implementation Prerequisites

- Claude·ChatGPT Codex·Cursor별 권위 있는 수집 경로, 접근 정책, 단위·공유 사용량 풀·한도·리셋·원본 시각을 검증해야 한다. 기존 provider 탐지는 실제 구독 quota 연동 완료가 아니다.
- SES의 α·초기화·bucket 단위·관측 완전성·실측 오차, 달력 비교 경계, 최신성 기준과 60초 수집 허용성을 검증해야 한다. 임의 상수나 가짜 데이터로 대체하지 않는다.
- 테마 저장/읽기 실패·재실행, OS 드래그/클릭, 포커스 복원·스크린리더·대비·작은 창을 구현에서 검증해야 한다. 이 초안은 실행 검증이 아니다.
- 원본 세션·경로·프롬프트·응답·자격증명·임의 메타데이터를 문서·화면·저장·로그에 추가하지 않는다. 허용된 비식별 집계만 사용한다.
