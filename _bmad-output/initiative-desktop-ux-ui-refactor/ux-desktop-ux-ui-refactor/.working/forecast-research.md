# 사용 속도와 리셋 전 여유·부족 전망 조사

상태: 지수평활 방식, 이력 기간 및 간결한 퍼센트 표시는 사용자 확정. 세부 파라미터는 설계 제안이며 제품 구현이나 실제 정확도 검증을 수행하지 않았다.

## 사용자 결정

- 단순 지수평활을 적용한다.
- 유효한 관측 이력이 7일 미만이면 사용 이력 부족으로 표시하고 전망 수치·소진 시각을 숨긴다.
- 7일 이상이면 필요한 한도·리셋 정보가 있을 때 계산 결과를 표시한다.
- 계산 입력으로 최근 7~30일 데이터를 사용한다. 30일을 넘는 이력이 있어도 계산에는 최근 30일만 투입한다. 종전 약 14일 고정 입력과 여러 모델 자동 선택 제안을 대체한다.
- 이는 계산 입력 기간이며 저장·보존 기간의 제한이 아니다. 30일 이전 데이터 삭제나 보존 정책 변경은 범위에 포함하지 않는다.
- 부족·여유 비율은 다음 리셋까지 예상 필요량 대비로 계산한다.
- 대시보드에 예측값이라는 직접적인 라벨을 붙이지 않는다.
- 필요량이 0이면 퍼센트 대신 적절한 상태 문구를 표시한다.
- 서비스 잔여량은 주간 60% 남음처럼 기간과 퍼센트로 표시한다. 가상 한도 단위나 계산식은 앱 화면에 노출하지 않는다.
- 보장 아님, 잔여 한도 퍼센트 아님 등의 면책성 문구는 화면에서 제거한다. 내부 계산 정의와 미확인 상태 처리는 유지한다.

## 표시 문구

서비스 요약은 주간 60% 남음, 20% 여유, 10% 부족처럼 짧게 표시한다. 잔여량과 사용 여유는 각각의 항목명으로 구별하며 면책 문장이나 수학식으로 설명하지 않는다. 아래 표의 의미 열은 내부 설계 설명이며 화면 문구가 아니다. 시안의 예시 데이터 표시는 앱 밖 검토용 캡션으로 분리한다.

| 상태                                  | 제안 문구                    | 의미                                                   |
| ------------------------------------- | ---------------------------- | ------------------------------------------------------ |
| D > 0, R > D                          | 20% 여유                     | 정해진 식으로 산출한 차이                              |
| D > 0, R < D                          | 20% 부족                     | 정해진 식으로 산출한 차이                              |
| D > 0, R = D                          | 필요량과 동일                | 여유가 추가로 확보되었다는 의미가 아님                 |
| 충분히 관측된 이력이 모두 0이고 R > 0 | 최근 사용 없음 · 잔여량 있음 | 앞으로도 충분하다고 보장하지 않음                      |
| 충분히 관측된 이력이 모두 0이고 R = 0 | 최근 사용 없음 · 잔여량 없음 | 0 필요량이 잔여 한도를 만들지는 않음                   |
| D = 0이나 관측 이력에 사용이 존재     | 사용 추세 확인 필요          | 모델 수치가 0이라고 최근 사용 없음으로 오표시하지 않음 |
| 관측 부족·누락                        | 사용 이력 부족               | 사용량 0과 구분                                        |
| 잔여량·리셋 미확인                    | 한도 정보 미확인             | 전망 비율과 소진 시각 미표시                           |
| 리셋 시각 경과, 새 한도 미수집        | 리셋 후 갱신 대기            | 기존 잔여량으로 계속 계산하지 않음                     |

## 조사한 방법

### 1. 단순 지수평활: 최근 변화 반영

관측 구간별 사용량을 y_t, 평활 수준을 l_t라고 할 때:

`l_t = α × y_t + (1 − α) × l_(t−1)`

`0 ≤ α ≤ 1`이며, 미래 구간 사용량은 마지막 수준 l_T로 산출한다. 최신 관측의 비중이 높아 최근 사용 속도 변화에 반응한다. 초기 수준과 α는 훈련 데이터만으로 정한다. 뚜렷한 계절성이나 추세가 있는 경우 이 방법 자체가 그것을 설명하지는 않는다.

### 2. 계절 단순법: 같은 요일·시간대 기준

미래 구간에 대응하는 직전 주의 같은 구간 사용량을 사용한다. 시간 단위 집계라면 주기 m=168, 일 단위라면 m=7이다. 요일·시간대 패턴의 비교 기준으로 사용한다. 14일에는 주간 반복이 두 번뿐이므로 주간 패턴을 정확히 학습했다고 단정할 수 없다.

### 3. 평균법: 비교 기준

관측된 동일 길이 구간들의 평균 사용량을 미래 구간에 적용한다. 고급 방법이 이 기준보다 실제로 나은지 평가하기 위해 포함한다. 평균법도 하나의 수학적 예측 방법이며 단순하다는 이유만으로 배제하지 않는다.

## 확정 방식의 검증 제안

제품에서 사용할 방식은 단순 지수평활로 고정한다. 계절 단순법과 평균법은 오차 비교용 기준이며 제품에서 자동으로 대체하는 모델이 아니다. 평활 계수 α와 초기 수준의 구체적인 산정 방식은 아직 미확정이다.

- 시간 순서대로 과거를 훈련하고 그 뒤의 이미 관측된 구간을 평가하는 rolling-origin 검증을 사용한다.
- 예측 시점 이후의 데이터나 그 데이터를 이용한 파라미터 조정이 훈련에 섞이지 않도록 한다.
- 목적은 다음 리셋까지의 누적 필요량이므로 한 구간의 오차뿐 아니라 서비스별 실제 리셋 주기에 대응하는 누적 사용량 오차를 평가한다.
- 0 사용이 가능하므로 0으로 나누는 MAPE를 기본 점수로 쓰지 않는다. 동일 서비스·단위·예측 기간에서 누적 사용량 MAE와 과소 산출 편향을 비교한다.
- 서비스마다 단위가 다르므로 오류 점수를 서비스 간에 직접 비교하지 않는다.
- 지수평활의 파라미터는 미래 정보를 이용하지 않고 산정하며, 검증 자료가 짧을 때 과도한 튜닝을 피한다.
- 7일은 표시를 시작하는 최소 이력 기준이지 정확도 보장이 아니다. 최근 최대 30일 자료도 월간 리셋 전망의 반복 검증에는 짧을 수 있다. 검증 구간 수, 관측일의 완전성 및 허용 수집 공백 기준은 구현 전 데이터 검토로 정한다. 근거 없이 높은 정확도나 확률을 표시하지 않는다.
- 실제 데이터 성능 검증은 수행하지 않았다. 지수평활 채택을 정확도 개선 완료라고 주장하지 않는다.

## 필요량과 소진 시각

각 미래 구간의 사용량 전망을 q_i, 현재부터 리셋까지 구간에 포함되는 비중을 f_i라고 하면:

`D = Σ(q_i × f_i)`

구간 일부의 수요를 비례 배분하는 것은 근사이며, 충분한 시간 단위 자료를 쓰면 이 오차를 줄일 수 있다. 관측 중인 불완전한 구간을 완전한 구간처럼 학습하지 않는다.

D > 0일 때만:

`여유·부족률 = (R − D) / D × 100`

소진 시각은 누적 미래 사용량이 R에 처음 도달하는 시점이다. 리셋 전 도달하지 않으면 임의의 리셋 이후 소진 시각을 만들지 않는다. 미래 사용량이 모두 0이면 무한대나 나눗셈 결과 대신 시각을 미표시한다. 내부 계산 정밀도와 화면 반올림을 분리한다.

## 데이터 전제와 한계

- 서비스·사용량 풀·한도 주기별로 별도 계산한다. 동시에 여러 한도가 있으면 각각 산출하며 하나의 합산 잔여 퍼센트를 만들지 않는다.
- 잔여량과 이력은 같은 단위여야 한다. 로컬 토큰이나 API rate limit으로 구독 한도를 대체하지 않는다.
- 주기별 누적 카운터는 리셋을 고려한 증분으로 변환해야 한다. 잔여량 변화는 추가 구매·플랜 변경에도 영향을 받으므로 사용량과 무조건 동일시하지 않는다.
- 수집 실패 구간을 0으로 채우지 않는다. 관측된 무사용 구간과 미관측 구간을 구분한다.
- 구독 한도가 소진되어 사용이 막힌 기간에는 수요가 억제된다. 낮은 관측 사용량만 보고 실제 필요량이 낮다고 확신하지 않는다.
- 미래 작업의 변화는 과거 이력만으로 알 수 없다. 계산 근거와 한계는 내부 설계 문서에 남기되 앱 화면의 면책성 문구로 노출하지 않는다.
- 개인정보나 계정 자격증명 접근 없이 문헌 조사만 수행했다.
