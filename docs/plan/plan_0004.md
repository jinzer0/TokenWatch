## 현재 저장소 상태

현재 구현은 다음 사실을 기준으로 한다.

- `AggregatorService.buildTuiData`는 현재 `overviewRows`, `budgetStatusRows`, `heatmapReport`/`activityRows`를 반환한다.
- `overviewRows`는 테이블 및 이벤트 수 중심의 데이터이며, 토큰/비용 KPI 카드 형태를 충분히 표현하지 않는다.
- `src/tui/App.tsx`의 `rowsForView`는 `overview`를 `data.overviewRows`에 매핑한다.
- 현재 Overview는 일반 `DataTable` 렌더링 경로를 사용한다.
- TUI view는 `overview`, `activity`, `budgets`를 포함한다.
- `BudgetStatusService`는 예산 상태 계산의 canonical 구현이며 privacy-hardened 되어 있다.
- 기존 TUI 아키텍처인 `App.tsx`, `state.ts`, 컴포넌트 구조, 키보드 내비게이션, details, current-view export, cache 동작은 보존해야 한다.

## 목표

TUI Overview를 KPI 대시보드 형태로 개선한다.

대시보드는 집계된 안전한 데이터만 표시해야 하며, 주요 정보 계층은 다음 순서를 따른다.

| 계층      | 표시 항목                                                                      |
| --------- | ------------------------------------------------------------------------------ |
| Primary   | Today, This Week, This Month, Budget                                           |
| Secondary | Total, Top source, Top sourceName, Top model, Unknown pricing, 선택적 Activity |

각 KPI는 명확한 label, 값, 단위, estimated 표시, unknown pricing 신뢰도 정보를 제공해야 한다. `Top: source · model · sourceName`처럼 모호한 통합 라벨은 최종 UI로 사용하지 않는다.

## 핵심 설계 원칙

1. Service-first DTO를 먼저 만든다.
2. Ink 컴포넌트는 presentational 역할만 한다.
3. 복잡한 집계, 기간 계산, top 계산, 예산 precedence 계산은 서비스 계층에서 끝낸다.
4. TUI renderer는 service DTO를 표시하고 responsive layout만 결정한다.
5. Current-view export/detail/cache는 기존 `overviewRows`를 유지하거나 새 DTO에서 sanitized rows로 명시적으로 mapping한다.
6. Budget summary는 `BudgetStatusService` 또는 `budgetStatusRows`의 canonical 결과를 재사용한다.
7. Budget math를 TUI에서 중복 구현하지 않는다.
8. Unknown pricing은 `null`/`unknown`으로 유지한다.
9. 누락 가격을 `$0.00`, free, zero로 표시하지 않는다.
10. Privacy sentinel은 rendered frame, details, footer/status text, export/cache/docs/smoke evidence 중 수정되는 경로마다 검증한다.

## Budget 규칙

Budget status는 canonical budget data에서 산출한다.

Precedence:

| 조건                                 | 결과             |
| ------------------------------------ | ---------------- |
| 설정된 budget이 없음                 | `not_configured` |
| 하나 이상 exceeded                   | `exceeded`       |
| exceeded는 없고 unknown 있음         | `unknown`        |
| exceeded/unknown은 없고 warning 있음 | `warning`        |
| 나머지 정상 상태                     | `ok`             |

여러 budget row가 있을 경우:

- monthly total budget이 있으면 Overview의 primary budget summary로 사용한다.
- 다른 budget row는 sanitized label과 요약 상태로만 보조 표시한다.
- raw path, raw session ID, raw metadata, SQL payload, stack trace 등은 표시하지 않는다.

## Unknown Pricing 규칙

Unknown pricing은 비용과 budget confidence 근처에 표시한다.

필수 동작:

- Unknown pricing count를 Overview에서 볼 수 있어야 한다.
- unknown cost는 `$0.00`으로 표시하지 않는다.
- unknown cost는 무료, zero, no cost처럼 오해될 문구로 표시하지 않는다.
- 기간별 cost가 일부 unknown일 수 있으면 estimated marker와 unknown pricing count를 함께 보여준다.

## Responsive Contract

Overview dashboard는 터미널 폭에 따라 다음 계약을 따른다.

| 폭     | 레이아웃                         | 필수 보존 항목                                                                                                      |
| ------ | -------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Wide   | 카드형 KPI dashboard             | 모든 primary/secondary KPI, label, token unit, estimated cost marker, budget status/progress, unknown pricing count |
| Medium | 2x2 primary KPI + secondary rows | Today/Week/Month/Budget primary, Total/top/unknown pricing secondary, overflow 없음                                 |
| Narrow | 명확한 labeled rows              | 필수 KPI label/value/unit/estimated marker/budget status/unknown pricing count 보존, horizontal overflow 없음       |

Compact fallback 규칙:

- Sparkline은 가장 먼저 생략한다.
- 장식 요소, border, spacing은 줄일 수 있다.
- 필수 KPI 값과 단위는 생략하지 않는다.
- unlabeled value-only 출력은 허용하지 않는다.
- narrow mode에서 horizontal overflow가 발생하면 실패로 간주한다.
