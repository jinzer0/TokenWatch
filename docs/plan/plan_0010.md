# Plan 0010: TokenWatch 릴리즈 통합 QA

## TL;DR

이미 구현된 다음 TokenWatch 기능군에 대해 릴리즈/통합 QA를 수행한다.

- Budget status / alert bar
- TUI Overview KPI dashboard
- Activity heatmap report
- Watch mode / live token velocity

이 문서는 실행 계획이며 실행 보고서가 아니다. 결과를 지어내지 않는다. 새 제품 기능을 추가하지 않는다. focused failing test 또는 격리 smoke check로 crash, privacy/security 문제, release blocker, 승인된 contract 위반이 증명된 경우에만 작은 수정을 허용한다.

## 지침 및 Preflight

remediation 전에 다음을 수행한다.

1. root guidance 읽기:
   - `AGENTS.md`

2. 관련 파일을 수정하기 전 해당 child guidance 읽기:
   - tests 수정: `tests/AGENTS.md`
   - services 수정: `src/services/AGENTS.md`
   - database behavior 수정: `src/db/AGENTS.md`
   - TUI 수정: `src/tui/AGENTS.md`
   - parser-adjacent behavior가 관련된 경우에만: `src/parsers/AGENTS.md`
   - desktop/package/native scope가 증명된 경우에만: `src/desktop/AGENTS.md`

3. clean tree를 요구하지 않고 dirty worktree를 분류한다.

```bash
git status --short
git diff --stat main...HEAD || git diff --stat
git diff --name-only main...HEAD || git diff --name-only
```

4. 다음을 분리한다.
   - Branch scope: release/integration feature branch 변경
   - Current dirty scope: 무관한 uncommitted user/agent 변경

5. 무관한 작업을 보존한다. 무관한 파일을 revert, overwrite, reformat, stage 하지 않는다.

6. 변경 파일을 분류한다.
   - CLI command
   - Services
   - Reports/renderers
   - TUI components/views
   - Tests
   - Docs/README
   - Package/build config
   - Desktop/package/native/dependency scope, 존재하는 경우

7. 기본 runtime health를 확인한다.

```bash
node --version
corepack pnpm --version
node -e "const Database = require('better-sqlite3'); const db = new Database(':memory:'); const row = db.prepare('select 1 as ok').get(); if (row.ok !== 1) process.exit(1); db.close();"
```

8. desktop/package/native conditional branch:
   - desktop, Electron, native module rebuild, packaging, dependency, lockfile, `package:mac` scope가 있으면 `src/desktop/AGENTS.md`를 읽고 이 계획의 conditional check를 실행한다.
   - 없으면 `N/A: preflight에서 desktop/package/native/dependency scope 없음`으로 기록한다.

## 검증 전략

TDD-oriented QA를 사용한다.

1. 정확한 변경 파일과 contract를 발견한다.
2. 변경 전에 승인된 behavior를 검토한다.
3. 가능한 경우 broad gate보다 focused test를 먼저 실행한다.
4. 필수 behavior가 실패하고 coverage가 없으면 가장 작은 focused failing test를 먼저 추가하거나 갱신한다.
5. 확인된 blocker에 대해서만 가장 작은 수정을 적용한다.
6. 실패했던 focused test 또는 smoke check를 다시 실행한다.
7. broad gate를 순차 실행한다.
8. built CLI smoke 전에 `corepack pnpm build`를 실행한다.
9. build 전에 smoke를 실행했다면 `built CLI smoke`가 아니라 `source-level smoke`로 표시한다.
10. 모든 CLI/TUI/report smoke에는 격리된 `TOKENWATCH_DB_PATH`를 사용한다.
11. sanitized evidence만 보고한다. raw stdout/stderr, raw diff, temp path, privacy sentinel, stack trace, SQL, arbitrary payload를 붙여 넣지 않는다.

Broad gate는 순차 실행한다.

```bash
corepack pnpm typecheck
corepack pnpm test
corepack pnpm lint
corepack pnpm format:check
corepack pnpm build
```

`format:check`는 classification-only이다. repository-wide format write를 실행하지 않는다.

preflight에서 관련 scope가 증명된 경우에만 conditional desktop/package/native gate를 실행한다.

```bash
corepack pnpm test:desktop
corepack pnpm build:desktop
corepack pnpm package:mac
node -e "const Database = require('better-sqlite3'); const db = new Database(':memory:'); const row = db.prepare('select 1 as ok').get(); if (row.ok !== 1) process.exit(1); db.close();"
```

### 2. Contract 및 Diff Review

**목표:** 각 feature family의 source of truth를 확정한다.

**Contract precedence:**

1. `AGENTS.md` 및 관련 child guidance
2. implementation/tests 안의 accepted feature contract 및 strict schema
3. focused tests 및 shared service implementation
4. CLI help, README, draft examples

**검토할 feature families:**

- Budget status / alert bar
- TUI Overview KPI dashboard
- Activity heatmap report
- Watch mode / live token velocity

**Cross-feature consistency checks:**

- Budget status enum은 `ok`, `warning`, `exceeded`, `unknown`으로 일관된다.
- Budget percent/progress는 CLI, TUI Overview, Budget Status, Watch budget summary 전반에서 일관된다.
- Unknown cost는 `null` 또는 `unknown`으로 유지된다. `$0.00`, free, zero, no-cost로 변환하지 않는다.
- Human output은 readable formatting을 허용하지만 JSON output은 raw number와 strict schema를 유지한다.
- Shared service가 source of truth이며 UI/report layer는 sanitized DTO를 소비한다.
- CLI, TUI, report file, export, docs, tests, errors, warnings 전반에서 privacy가 유지된다.

**Acceptance Criteria:**

- 각 feature family의 implementation, test, docs/help surface가 식별된다.
- 새 feature scope가 도입되지 않는다.
- mismatch는 implementation bug, test expectation issue, doc/help mismatch, environment issue, unrelated failure, known limitation으로 분류된다.

### 3. Focused TDD Tests

**목표:** broad gate 전에 focused test로 behavior를 검증한다.

**예상 focused commands:**

```bash
corepack pnpm test -- tests/budgetService.test.ts
corepack pnpm test -- tests/watchService.test.ts
corepack pnpm test -- tests/watchCli.test.ts
corepack pnpm test -- tests/heatmapService.test.ts
corepack pnpm test -- tests/heatmapCli.test.ts
corepack pnpm test -- tests/reportContracts.test.ts
corepack pnpm test -- tests/cliProcess.test.ts -t "<budget|heatmap|watch|privacy|help focused pattern>"
corepack pnpm test -- tests/aggregatorTui.test.tsx
```

executor는 preflight에서 현재 파일과 test name을 확인한 뒤 정확한 focused command를 조정할 수 있다.

**Acceptance Criteria:**

- Focused tests가 PASS하거나 failure가 분류된다.
- 모든 fix는 failing focused test 또는 isolated smoke check와 연결된다.
- 무관한 failure는 보고하되, 사용자가 scope를 확장하지 않는 한 수정하지 않는다.

### 4. Minimal Remediation Loop

**목표:** 증명된 release blocker 또는 accepted contract violation만 수정한다.

**허용되는 수정:**

- Crash fix
- Security/privacy leak fix
- Required smoke failure fix
- Accepted strict schema/contract fix
- 구현과 맞추기 위해 필요한 최소 docs/help correction

**허용되지 않는 수정:**

- Feature addition
- Large refactor
- accepted contract가 요구하지 않는 public schema/API change
- Repository-wide formatting write
- Parser expansion
- preflight에서 branch가 활성화되지 않은 desktop/package broadening

**Loop:**

1. sanitized failure classification을 기록한다.
2. 가능하면 focused failing test를 추가하거나 갱신한다.
3. 최소 수정을 적용한다.
4. focused test 또는 smoke를 다시 실행한다.
5. 영향을 PASS, PASS_WITH_FIXES, FAIL로 기록한다.

**Acceptance Criteria:**

- 모든 remediation은 증명된 failure reason을 가진다.
- 각 fix 후 focused check가 다시 실행된다.
- 무관한 파일은 변경되지 않는다.
- privacy contract가 약화되지 않는다.

### 5. Broad Gates

**목표:** 저장소 단위 릴리즈 준비 상태를 확인한다.

순차 실행한다.

```bash
corepack pnpm typecheck
corepack pnpm test
corepack pnpm lint
corepack pnpm format:check
corepack pnpm build
```

**Acceptance Criteria:**

- release-ready PASS를 위해 required gate가 PASS한다.
- `format:check`는 classification-only이다.
- 모든 failure가 분류된다.
- 해결되지 않은 required failure, privacy leak, environment blocker, required NOT_RUN check는 FAIL을 만든다.
- unrelated failure는 보고하고 수정하지 않지만, required gate를 막으면 unqualified release-ready PASS를 막는다.

### 6. Built CLI, TUI, Report Smoke

**목표:** 격리 data로 runtime behavior를 검증한다.

**Precondition:** built CLI smoke 전에 `corepack pnpm build`가 PASS해야 한다.

**Environment:** 모든 CLI/TUI/report smoke에 isolated temp DB를 사용한다.

```bash
TOKENWATCH_DB_PATH=<temporary-db-path>
```

default DB를 사용하지 않는다.

**Synthetic data requirements:**

semantic smoke에는 synthetic/runtime-aligned data를 사용한다.

- current-local-month budget rows/events
- UTC heatmap-year events
- runtime-relative Watch events
- repeated `source` 및 `sourceName` filters
- mixed known/unknown pricing
- privacy-marker cases

Static seed는 non-crash만 증명할 수 있다.

**Built CLI smoke commands:**

```bash
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js --help
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js seed
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js summary
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js budget set --scope monthly_total --threshold 25
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js budget status
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js budget status --json
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --json
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --metric tokens
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --metric cost
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --metric events
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js watch --once
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js watch --once --json
```

**Repeated filter smoke:**

```bash
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --source codex --source opencode --source-name local --source-name lab-server --json
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js watch --once --source codex --source opencode --source-name local --source-name lab-server --json
```

**Heatmap file output smoke:**

```bash
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --out <temporary-output-dir>/heatmap.json
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --out <temporary-output-dir>/heatmap.txt
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js heatmap --out <temporary-output-dir>/heatmap.svg
node -e "JSON.parse(require('node:fs').readFileSync(process.argv[1], 'utf8'))" <temporary-output-dir>/heatmap.json
```

파일 내용은 붙여 넣지 않고 다음을 검증한다.

- `.json` parse 가능
- `.txt` readable
- `.svg`에 `<svg` 포함
- `.svg`에 remote script, external font URL, remote resource reference 없음
- output에 prompt, response, credential, raw path, raw session ID, raw record, SQL payload, stack trace, arbitrary metadata dump 없음

**TUI verification:**

환경이 지원하면 manual TUI smoke를 시도한다.

```bash
TOKENWATCH_DB_PATH=<temporary-db-path> node dist/cli.js tui
```

검증한다.

- Navigation에 render 가능한 view가 존재한다.
- Help view가 실제 key 및 view name과 일치한다.
- Overview KPI dashboard가 render된다.
- Budget Status view가 canonical status/progress를 표시한다.
- 구현된 경우 Activity Heatmap view가 render된다.
- Watch/Live TUI view를 지어내지 않는다. 구현되지 않았다면 `N/A: Watch/Live TUI view not implemented`로 표시한다.
- 검증 가능한 경우 narrow terminal fallback이 crash하지 않는다.
- Theme setting과 충돌하지 않는다.
- Selected row/detail panel behavior가 crash하지 않는다.

**Fallback rule:**

- interactive TUI를 실행할 수 없으면 manual TUI를 reason과 함께 `NOT_RUN`으로 보고한다.
- `tests/aggregatorTui.test.tsx`와 code review evidence를 automated fallback으로 사용한다.
- fallback을 manual PASS로 바꾸지 않는다.

**Cleanup:**

sanitized evidence를 기록한 뒤 temporary DB/WAL/SHM 파일과 temporary output directory를 제거한다. 사용자가 failing artifact 보존을 명시적으로 요청하지 않는 한 raw evidence dump를 영구 생성하지 않는다.

### 7. Privacy Sweep

**목표:** helpers, strict schemas, allowlists, bounded errors로 privacy를 검증한다.

**Required approach:**

- 가능한 경우 `containsPrivacySentinel` 같은 기존 privacy helper를 사용한다.
- JSON/report output에 strict schema/allowlist validation을 적용한다.
- Error 및 warning이 bounded/sanitized 되었는지 assert한다.
- Sentinel absence만으로는 충분하지 않다.
- 의도적인 sentinel fixture/source text는 leak가 아니다.
- evidence에 sentinel string, raw output, stack trace, SQL, temp path, arbitrary payload를 붙여 넣지 않는다.

**Surfaces:**

- `budget status`
- `budget status --json`
- TUI Overview
- TUI Budget Status
- `heatmap`
- `heatmap --json`
- `heatmap --out .json`
- `heatmap --out .txt`
- `heatmap --out .svg`
- `watch --once`
- `watch --once --json`
- 실행한 경우 watch loop tick output
- TUI Activity Heatmap
- 구현된 경우 TUI Watch/Live view, 아니면 N/A
- README/docs examples
- Tests/snapshots
- Error messages
- Warnings

**Acceptance Criteria:**

- 어떤 release surface도 disallowed private data를 emit하지 않는다.
- JSON/report output이 strict safe schema와 일치한다.
- Error 및 warning이 bounded/sanitized 되어 있다.
- Privacy leak는 release blocker이며, 수정 후 rerun하지 않으면 FAIL이다.

### 8. Edge Case Review

**목표:** 모든 non-blocker를 강제로 고치지 않고 edge case를 검토한다.

검토 대상:

- No DB file
- Empty DB
- No usage events
- No budgets configured
- Budget threshold zero or invalid
- All costs unknown
- Mixed known/unknown costs
- Leap year heatmap
- Invalid heatmap metric
- Invalid heatmap year
- Invalid watch interval
- Invalid watch window
- Multiple source filters
- `sourceName` filter with no match
- Narrow terminal width
- JSON output redirected to file
- Output path directory missing or unwritable

**Fix rule:** 확인된 crash, security/privacy issue, release blocker, accepted core contract violation만 수정한다. 그 외는 final executor response의 known limitation으로 문서화한다.

**Acceptance Criteria:**

- 모든 edge case가 reviewed 또는 reason이 있는 NOT_RUN으로 표시된다.
- Required failure는 수정되거나 FAIL을 만든다.
- Known limitation은 release blocker와 명확히 분리된다.

- Broad gate가 순차 실행되었다.
- Built CLI smoke 전에 build가 실행되었다.
- CLI/TUI/report smoke가 isolated `TOKENWATCH_DB_PATH`를 사용했다.
- Evidence는 sanitized table만 사용한다.
- Raw stdout/stderr, raw diff, temp path, sentinel, stack trace, SQL, arbitrary payload가 붙여 넣어지지 않았다.
- Temporary DB/WAL/SHM/output artifact가 명시적 보존 요청 없이는 정리되었다.
- README/help parity가 확인되었다.
- Release summary가 final executor response에 준비되었다.

**Status criteria:**

- PASS: required gate와 required smoke가 unresolved blocker 없이 PASS.
- PASS_WITH_FIXES: 최소 confirmed fix를 적용했고 rerun이 PASS.
- FAIL: required gate 실패, privacy leak 잔존, environment blocker로 required verification 불가, required check가 NOT_RUN.
- Unrelated failure는 보고하고 수정하지 않지만, required gate를 막으면 unqualified release-ready PASS를 막는다.

## Commit Policy

사용자가 명시적으로 요청하지 않는 한 commit하지 않는다.

commit이 요청되면 concern별 atomic commit을 사용한다.

- `test: cover release integration regression`
- `fix: align <feature> release behavior`
- `docs: align release QA documentation`
- `chore: record release integration QA plan`

commit 전 확인한다.

```bash
git status --short
git diff
git log --oneline -10
```

의도한 파일만 stage한다. 무관한 작업을 보존한다. 저장소의 semantic English commit style과 `AGENTS.md`의 required attribution을 따른다.

## Success Criteria

release/integration QA 작업은 다음 조건을 만족하면 완료된다.

- Preflight, guidance, dirty-scope classification, runtime health가 완료되었다.
- 가능한 경우 broad gate보다 focused test를 먼저 실행했다.
- Broad gate를 순차 실행했다.
- Built CLI smoke 전에 build가 PASS했다.
- CLI/TUI/report smoke가 isolated temp DB를 사용했다.
- Synthetic/runtime-aligned data가 semantic smoke requirement를 충족했다.
- Privacy sweep이 helper, strict schema/allowlist, bounded error assertion을 사용했다.
- TUI manual verification이 PASS이거나, reason이 있는 NOT_RUN과 automated fallback evidence가 있다.
- Conditional desktop/package/native check가 PASS이거나 명시적 N/A이다.
- Edge case가 검토되었고 blocker만 수정되었다.
- Final response가 strict criteria로 PASS, PASS_WITH_FIXES, FAIL을 보고한다.
- 새 product feature가 추가되지 않았다.
- Persistent raw evidence dump가 생성되지 않았다.
