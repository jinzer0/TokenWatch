# TokenWatch Watch, Heatmap, Budget Status, TUI Dashboard 구현 계획

> 출처 메모: 이 계획은 `docs/draft/draft_0001.md`, adversarial hyperplan bundle, 그리고 읽기 전용 레포 검토를 통합한 것이다. 이 문서를 작성하는 동안 어떤 파일도 수정하지 않았다.

## 목표

다음 네 가지 privacy-safe, local-first 기능군을 구현한다.

1. `tokenwatch watch`: polling 기반 live delta 및 velocity 리포팅. `--once`를 deterministic primitive로 둔다.
2. TUI Overview KPI dashboard: shared service data를 기반으로 한 카드형 Overview 요약.
3. Activity heatmap: 연간 token, event, cost 활동량을 보여주는 CLI/report 출력.
4. Budget alert/status 개선: CLI, TUI, watch가 재사용하는 중앙화된 status 및 progress-bar 계산.

구현은 TokenWatch의 privacy boundary를 반드시 유지해야 한다. prompts, responses, credentials, API keys, OAuth tokens, raw paths, raw session IDs, raw payloads, raw records, SQL payloads, stack traces, arbitrary raw metadata를 저장, 출력, 렌더링, export, log, screenshot, snapshot 어디에도 포함하면 안 된다.

Unknown pricing과 unknown cost는 정상적인 correctness state다. Missing prices는 반드시 `null`/`unknown`으로 남겨야 하며, `$0.00`, free, zero-cost로 바꾸면 안 된다.

## 아키텍처 결정

### Shared Contracts First

Rendering보다 먼저 stable DTO를 정의하고 테스트한다.

- Watch tick DTO
- Heatmap report DTO
- Budget status DTO
- Renderer input DTOs
- Privacy object/flag shape

기존 report/statusline contract가 Zod schema를 사용하는 곳에서는 Zod schema를 우선 사용한다.

모든 새 JSON output은 다음을 포함해야 한다.

- `version`
- `kind`
- deterministic typed fields
- test determinism이 필요한 경우 injected clock에서 나온 `generatedAt` 또는 `timestamp`
- `privacy: { sanitized: true }` 또는 기존과 동등한 privacy shape

Merge 이후 breaking JSON change는 version/schema update와 테스트가 필요하다.

### Centralized Budget Status

하나의 shared budget status/progress computation service를 만들거나 그 방향으로 refactor한다. 잠정 target:

- `src/services/budgetStatusService.ts`

이 service는 기존 budget thresholds/evaluations와 usage events를 소비하거나, 가장 작은 safe seam이 `BudgetService.evaluateCurrentMonth()`라면 이를 감싸도 된다.

다음 소비자들이 하나의 canonical status model을 사용해야 한다.

- `tokenwatch budget status`
- `tokenwatch budget status --json`
- TUI Budget view progress bars
- TUI Overview budget card
- `tokenwatch watch` budget summary
- 실용적이면 기존 statusline/budget-pressure path

Target statuses:

- `ok`: warning threshold 미만
- `warning`: warning threshold 이상, threshold 미만
- `exceeded`: threshold 이상
- `unknown`: material unknown cost 때문에 확정 판단이 어려운 상태

기존 `BudgetService` status와의 mapping은 명시적이고 test-backed여야 한다. CLI/TUI/watch에 threshold rule copy를 남기지 않는다.

### Unknown Cost Policy

Cost metric 전체에 적용한다.

- Known spend는 non-null `estimatedCostUsd`만 합산한다.
- Missing prices는 `null`로 유지하거나 `unknown`으로 표시한다.
- Unknown-cost events는 별도로 count한다.
- Heatmap cost totals에는 `unknownCostEvents`를 포함한다.
- Unknown-cost events가 threshold 판단을 불확실하게 만들면 budget status는 `unknown`이 될 수 있다.
- Unknown cost를 `$0.00`으로 바꾸면 안 된다.

### Watch Mode Policy

Polling을 먼저 구현한다. `fs.watch`를 요구하지 않는다.

`watch --once`가 primary testable primitive다.

- 한 번 snapshot/delta/velocity tick을 계산한다.
- Text 또는 stable JSON을 출력한다.
- 종료한다.

Continuous `watch`는 같은 service를 interval마다 반복 호출해야 한다.

Pure calculation functions는 injected timestamps 또는 clock object를 받아야 한다.

- Snapshot selection
- Delta calculation
- Velocity calculation
- Top source/sourceName/model/agent selection
- Budget summary assembly

Minimum interval은 5초다. Invalid interval은 bounded privacy-safe error로 실패한다.

### Heatmap Output Policy

지원 output format:

- Text to stdout
- JSON to stdout
- `.json` file
- `.txt` file
- `.svg` file

PNG는 implementation이 기존 reusable renderer를 명확히 확인하고 privacy/complexity risk 없이 작게 유지할 수 있을 때만 scope에 포함한다.

Text output은 color에만 의존하면 안 된다. Density characters와 labels를 사용한다.

### TUI Last

TUI는 shared summaries와 renderer-safe DTO를 소비해야 한다. Budget status, heatmap levels, watch deltas, unknown-cost rules를 독립적으로 재계산하면 안 된다.

Narrow terminal fallback은 필요하지만 단순해야 한다.

- Cards가 fit하지 않으면 compact rows를 우선한다.
- Responsive layout을 과설계하지 않는다.
- 기존 keyboard contract를 유지한다.

## Atomic Commit Strategy

다음 순서의 작은 commits를 사용한다.

1. `test: lock watch heatmap budget status contracts`
2. `feat: centralize budget status computation`
3. `feat: add budget status command`
4. `feat: add watch once service and cli`
5. `feat: add heatmap report service and renderers`
6. `feat: add heatmap cli outputs`
7. `feat: integrate dashboard budget and activity tui views`
8. `test: expand privacy sentinels for live report surfaces`
9. `docs: document watch heatmap and budget status`

각 commit은 다음 단계로 넘어가기 전에 narrow related test target을 통과해야 한다. 최종 branch는 full verification gate를 통과해야 한다.

## Acceptance Criteria

모든 조건이 참일 때만 완료다.

- `tokenwatch watch --once`가 동작한다.
- `tokenwatch watch --once --json`이 stable privacy-safe JSON을 출력한다.
- Continuous `tokenwatch watch`는 polling을 사용하고 `--once` computation path를 재사용한다.
- `tokenwatch budget status`가 동작한다.
- `tokenwatch budget status --json`이 stable privacy-safe JSON을 출력한다.
- Budget progress/status logic은 중앙화되어 CLI, TUI, watch가 재사용한다.
- `ok`, `warning`, `exceeded`, `unknown` budget statuses가 test-backed다.
- Unknown pricing은 `$0.00`이 아니라 `null`/`unknown`으로 유지된다.
- `tokenwatch heatmap`이 terminal-safe text를 출력한다.
- `tokenwatch heatmap --json`이 stable privacy-safe JSON을 출력한다.
- `tokenwatch heatmap --out *.json`, `*.txt`, `*.svg`가 동작한다.
- Heatmap cost reports가 `unknownCostEvents`를 count한다.
- TUI Overview가 KPI dashboard data를 보여준다.
- TUI Budget이 shared progress/status rows를 사용한다.
- TUI Heatmap/Activity가 shared heatmap summaries를 사용한다.
- Narrow terminal rendering이 crash하지 않는다.
- README/docs가 업데이트된다.
- Privacy sentinels가 모든 새 stdout, stderr, JSON, TXT, SVG, TUI, export, docs example surfaces에 없다.
- `corepack pnpm typecheck`, `corepack pnpm test`, `corepack pnpm lint`, `corepack pnpm format:check`, `corepack pnpm build`가 통과하거나, 실패가 environment/native-module인지 code-related인지 정확히 분류된다.
- Isolated DB smoke checks는 `TOKENWATCH_DB_PATH=/tmp/...`를 사용한다.

## 제한 사항

- Cost는 estimate이며 billing-grade truth가 아니다.
- Unknown model pricing은 cost와 budget status를 unknown으로 만들 수 있다.
- Watch mode는 polling-based이며 filesystem event watcher가 아니다.
- Heatmap PNG는 기존 reusable renderer가 발견되고 명시적으로 검증되지 않는 한 포함하지 않는다.
- Shared analytics contracts를 의도적으로 desktop에서 재사용하지 않는 한 desktop changes는 필요하지 않다.
- 이 계획은 읽기 전용 검토에 기반해 tentative files를 지목한다. 구현자는 편집 전 exact seams를 확인해야 한다.

## Draft 대비 변경점과 이유

- Draft를 requirements dump에서 ordered implementation phases로 재구성했다.
  Reason: implementation은 contracts/services를 먼저 고정하고, 그다음 CLI/report outputs, TUI, docs/verification 순서로 진행해야 한다.

- Shared JSON contracts를 first-class deliverables로 올렸다.
  Reason: watch, heatmap, budget status는 text/TUI rendering layer가 의존하기 전에 stable, test-backed schemas가 필요하다.

- Budget status를 하나의 service로 중앙화했다.
  Reason: CLI, TUI, watch, statusline에 `ok`/`warning`/`exceeded`/`unknown` rule을 중복하면 inconsistent behavior가 생긴다.

- 기존 repo seams를 명시하고 verify 대상이라고 표시했다.
  Reason: 읽기 전용 검토 결과 adjacent services와 tests는 있지만 기존 `watch`, `heatmap`, `budget status` command는 확인되지 않았다. 계획은 확인하지 않은 implementation detail을 invent하지 않는다.

- `watch --once`를 primitive로 승격했다.
  Reason: deterministic one-shot execution은 테스트하기 쉽고, continuous watch는 같은 path를 반복 polling하면 된다.

- Filesystem watchers를 요구하지 않도록 했다.
  Reason: polling은 local-first CLI에서 더 예측 가능하고 bundle의 reliability constraint와 맞다.

- Unknown pricing/cost handling을 더 엄격하게 했다.
  Reason: missing prices는 `$0.00`이 되면 안 되며, heatmap과 budget status는 unknown cost를 meaningful state로 다뤄야 한다.

- Heatmap PNG를 required scope에서 제거했다.
  Reason: SVG/TXT/JSON만으로 feature를 충족하며, PNG는 image-renderer complexity를 강제한다. 기존 reusable renderer가 검증될 때만 허용한다.

- TUI를 명시적으로 마지막 단계로 옮겼다.
  Reason: TUI는 shared summaries를 소비해야 하며 aggregation, budget, heatmap, watch rules를 재구현하면 안 된다.

- Privacy sentinel testing을 모든 새 output surface로 확장했다.
  Reason: 새 commands는 stdout, JSON, file, SVG, TUI surfaces를 추가하므로 TokenWatch privacy guarantee regression 위험이 있다.

- Tests를 TDD-oriented로 만들고 brittle snapshots를 피했다.
  Reason: Contract fields와 sentinel absence는 full terminal frame snapshots보다 안정적이다.

- Verification에 isolated DB smoke checks를 추가했다.
  Reason: CLI/TUI/database surfaces는 real user data나 default DB를 건드리면 안 된다.

- Atomic commit strategy를 포함했다.
  Reason: 이 작업은 contracts, services, CLI, reports, TUI, tests, docs를 가로지르므로 작은 commits가 review와 rollback을 쉽게 한다.
