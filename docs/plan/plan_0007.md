## Authoritative Current-Contract Decisions

### Contract Precedence

When sources conflict, use this precedence:

4. Illustrative draft JSON samples and sample commands.

Illustrative draft examples are not authoritative when they conflict with the shipped v1 contract.

### Heatmap JSON Contract

The authoritative heatmap report contract is:

- `version: 1`
- `kind: "heatmap"`
- `generatedAt`
- `year`
- `metric`, supporting `tokens`, `events`, and `cost`
- UTC half-open range: start inclusive, end exclusive
- `filters.source` as an array
- `filters.sourceName` as an array
- `totals`
- `days[]`
- each day includes `date`, `events`, `totalTokens`, `estimatedCostUsd`, `unknownCostEvents`, `value`, and `level`
- `legend[]` as an item array with symbols
- `privacy: { sanitized: true }`

The stale draft sample shape is explicitly rejected as the target contract where it uses:

- `null` filters
- object-shaped legend
- four separate privacy booleans

### Filter Semantics

- Repeated `source` values are OR within `source`.
- Repeated `sourceName` values are OR within `sourceName`.
- `source` and `sourceName` combine with AND.
- Unsupported source adapter input must produce a bounded, sanitized, nonzero error.
- Unknown but valid `sourceName`, or a supported source with no rows, should produce an empty 365/366-day report.

### Year Boundary Decision

Use supported year range `1970..9998`.

Reason:

- The v1 contract uses four-digit UTC datetime strings.
- Supporting year `9999` with a half-open next-year exclusive range would require an end timestamp in year `10000`.
- ISO serialization for year `10000` becomes expanded form such as `+010000...`, which conflicts with the current four-digit datetime schema.
- Therefore year `9999` is rejected unless a future explicit schema/docs/test change adopts expanded ISO years.

Required boundary tests:

- `1969` is rejected.
- `1970` is accepted.
- `9998` is accepted.
- `9999` is rejected.
- `10000` is rejected.

Docs, CLI validation, schema expectations, and tests must align on `1970..9998`.

### Unknown Cost Semantics

- Cost value is the known-cost sum.
- A day with only unknown-cost events has `value: 0`, `estimatedCostUsd: null`, and `unknownCostEvents > 0`.
- That state means “unknown cost,” not free.
- Renderers must expose unknown count/state.
- Renderers must never display unknown cost as `$0.00`, `free`, or equivalent zero-cost wording.

### Phase 7: Manual CLI QA

Required rules:

- Set `TOKENWATCH_DB_PATH="$DB"` on every command.

## Per-Defect Repair Loop

Handle one defect at a time.

For each defect:

1. Reproduce the defect with the smallest command or test.
2. Classify it:
   - service/schema
   - CLI/file output
   - SVG
   - TUI Activity
   - docs/example
   - privacy
   - environment/unrelated
3. Add or strengthen the narrow failing regression test first.
4. Make the minimal in-scope fix.
5. Rerun the narrow failing test.
6. Rerun affected adjacent surface tests.
7. Rerun manual QA only for affected smoke cases unless the fix changes shared behavior.
8. Rerun broad gates as required by the changed files.
9. Record the defect, fix, and rerun evidence.
10. Do not batch unrelated fixes.

If a defect appears to require a DB migration, index redesign, API redesign, desktop packaging change, new dependency, or renderer rewrite:

- Stop and document why the smaller fix is insufficient.
- Proceed only if the defect is reproducible and the larger change is the minimal safe remediation.

## Atomic Commit Strategy

Do not commit unless execution scope explicitly includes committing.

When commits are requested:

- Keep commits atomic by concern.
- Prefer one commit per repaired defect.
- Include the failing/strengthened regression test and the minimal fix in the same commit when they prove the same behavior.
- Use a separate docs-only commit for plan/docs wording when applicable.
- Do not bundle unrelated cleanup or formatting.
- Inspect `git status`, `git diff`, and recent log before committing.
- Stage only intended files.
- Use the repository’s semantic commit style, such as:
  - `test: add heatmap year boundary regressions`
  - `fix: enforce heatmap year range`
  - `fix: preserve heatmap filter arrays`
  - `docs: align heatmap contract examples`
- Include the required attribution body and trailer:

```text
Ultraworked with [Sisyphus](https://github.com/code-yeongyu/oh-my-openagent)

Co-authored-by: Sisyphus <clio-agent@sisyphuslabs.ai>
```

## Final Report Requirements

The final report must be deterministic and include one of these statuses:

- `PASS`
- `PASS_WITH_FIXES`
- `FAIL`

Status definitions:

- `PASS`: all mandatory gates and smoke checks pass with no fixes applied.
- `PASS_WITH_FIXES`: defects were found, fixed with regression coverage, and all required reruns pass.
- `FAIL`: an unresolved in-scope defect remains, or a required gate/smoke check cannot complete.
- Environment blockers or unrelated failures prevent unqualified `PASS`.

The final report must include:

- Final status.
- Reviewed content and surfaces.
- Command table with command, purpose, exit code, and result.
- Manual QA matrix with isolated DB path pattern, output path, command purpose, and observed result.
- Found issues.
- Applied fixes.
- Regression tests added or strengthened.
- Reruns performed.
- Remaining risks.
- Explicit blockers.
- Environment or unrelated failures, if any, separated from in-scope defects.
- Privacy validation results for emitted/runtime surfaces and published examples.
