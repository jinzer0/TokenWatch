# TokenWatch Node.js + Ink MVP 최종 구현 계획

> Provenance: Hyperplan adversarial review와 plan-agent handoff를 반영한 수정 최종 계획이다. 이 문서는 기존 프롬프트를 그대로 반복하지 않고, 범위 과확장, 개인정보 누출, parser 불확실성, 중복 방지, source attribution, 검증 누락을 보완한 실행 계약이다.

## 1. 목표

TokenWatch는 개인 노트북과 연구실 서버에서 실행된 AI coding agent의 LLM token usage metadata를 로컬 SQLite DB에 저장하고, CLI와 Ink TUI에서 집계해 보여주는 local-first 터미널 앱이다.

MVP는 얇지만 실제 동작해야 한다. 모든 필수 명령어와 TUI 화면은 `coming soon` stub이 아니라, 제한된 범위 안에서 실제 데이터 경로, 검증, 오류 처리를 갖춘다.

## 2. 참조 경계와 비목표

`docs/tokscale`는 reference-only이다. Rust, Python, web/frontend, 기존 Tokscale 구조, DB schema, parser 구현, native packaging, social/dashboard 기능은 구현에 재사용하지 않는다.

MVP에서 하지 않는다.

- Python backend, Python parser, Typer CLI, Node/Python bridge
- Rust/Tokscale implementation porting
- web dashboard, daemon, central collector, cloud sync, real-time monitoring
- OpenAI OAuth/API usage pull, API key/OAuth token 저장 또는 재사용
- auth, multi-user, notification, budget policy, Kubernetes, menu bar app
- prompt/response 원문 저장, raw transcript/detail viewer
- 모든 Codex/OpenCode 과거 버전의 완전 지원 또는 billing-grade cost 보장

## 3. 기술 결정

- Runtime: Node.js `>=20.11`
- Package manager: `pnpm`
- Language: TypeScript strict mode
- Module: native ESM
- CLI: Commander.js with `parseAsync`
- TUI: Ink + React
- DB: SQLite via `better-sqlite3`
- Validation: Zod
- Test: Vitest
- Formatter/Linter: Prettier + ESLint
- Binary: `package.json`의 `bin.tokenwatch`가 shebang이 있는 built JS를 가리킨다.
- DB path: 기본 `~/.tokenwatch/tokenwatch.db`, override `TOKENWATCH_DB_PATH`
- `better-sqlite3` native dependency 위험은 README와 `doctor`에 명시한다.

## 4. 용어와 canonical semantics

| 용어 | 의미 |
| --- | --- |
| `source` | parser/adapter type. MVP 값은 `codex`, `opencode`. CLI `scan --source`와 같은 개념이다. |
| `sourceName` | laptop/server/lab attribution label. 우선순위는 `--source-name`, config `source_name`, 기본값 `local`. |
| `agent` | 안전하게 알 수 있는 coding-agent/product identity. 모르면 adapter identity로 default한다. |
| `rawSource` | 안전한 artifact format enum-like 값. 예: `codex-jsonl`, `opencode-sqlite`. raw path/payload가 아니다. |
| `sessionIdHash` | session identifier의 hash. 원문 session ID는 저장하지 않는다. |
| `rawIdHash` | raw record/file/db row identity의 optional hash. 원문 path/row payload는 저장하지 않는다. |
| `metadata` | allowlisted parser metadata만 허용한다. arbitrary JSON dump는 금지한다. |

`sourceName`은 canonical event, SQLite schema, Zod schema, export/import, summary, TUI detail에 모두 포함한다. `source_name` 변경은 이후 scan/import에만 적용하고 기존 event ID나 row를 rewrite하지 않는다.

## 5. Canonical Usage Event

필수 필드:

- `id`
- `timestamp`
- `source`
- `sourceName`
- `agent`
- `provider`
- `model`
- `inputTokens`
- `outputTokens`
- `totalTokens`
- `rawSource`

선택 필드:

- `cachedTokens`
- `reasoningTokens`
- `estimatedCostUsd`
- `sessionIdHash`
- `rawIdHash`
- `metadata`

정책:

- `timestamp`는 UTC ISO string으로 저장한다.
- day/hour grouping은 기본적으로 local time 기준으로 표시한다. 테스트에서는 fixed timezone 또는 injected clock을 사용한다.
- token count는 non-negative integer만 허용한다.
- 하나 이상의 usage token field가 있으면 누락 bucket은 `0`으로 normalize할 수 있다.
- token evidence가 전혀 없는 record는 skip한다.
- `totalTokens`는 helper에서 계산 또는 검증한다. cached/reasoning token은 pricing helper에서 명시적으로 다루며 중복 집계하지 않는다.
- `estimatedCostUsd`는 nullable SQLite `REAL`로 저장한다. 표시 시 deterministic rounding을 적용하고 테스트는 tolerance를 둔다.
- unknown pricing은 `null`이며 `0`으로 저장하지 않는다.

## 6. Event fingerprint와 dedupe

Parser가 각자 ID를 만들지 않는다. 중앙 fingerprint utility가 sanitized canonical fields로 deterministic ID를 생성한다.

Fingerprint material에 포함한다.

- normalized `timestamp`
- `source`
- `sourceName`
- `agent`
- `provider`
- `model`
- token tuple
- `rawSource`
- `sessionIdHash` if available
- `rawIdHash` 또는 안전한 parser record identity/ordinal hash if available

Fingerprint material에 절대 포함하지 않는다.

- raw path
- raw JSON/JSONL payload
- prompt/response text
- auth/API/OAuth token
- repo name/private file content
- arbitrary metadata
- export timestamp 같은 volatile field

DB는 `usage_events.id`를 primary key로 강제한다. 같은 ID가 다시 들어오면 duplicate로 count하고 overwrite하지 않는다. 같은 ID인데 canonical payload가 다르면 conflict로 보고하고 기존 row를 유지한다.

## 7. SQLite schema와 repository

MVP schema는 migration 기반으로 초기화한다. `app_config` 또는 `schema_migrations`에 schema version을 저장하고 startup 시 idempotent migration을 실행한다.

핵심 테이블:

- `usage_events`
- `scan_runs`
- `pricing_models`
- `app_config`

`usage_events`에는 원래 필드에 더해 최소한 `source_name`, `raw_id_hash`, `pricing_version` 또는 equivalent metadata를 추가한다. Aggregation을 위해 `timestamp`, `source`, `source_name`, `agent`, `provider`, `model`, `raw_source`에 필요한 index를 둔다.

DB 정책:

- 모든 write는 repository layer를 통한다.
- scan/import는 transaction으로 처리한다.
- `scan_runs`는 started/completed/failed/interrupted status, discovered/opened candidate count, parsed/rejected/inserted/duplicate/skipped/error count, bounded sanitized warnings를 기록한다.
- SQLite는 WAL + `busy_timeout`을 사용하거나 single-writer policy를 명시한다.
- TUI와 CLI는 DB에 직접 SQL을 흩뿌리지 않고 shared query/aggregation service를 사용한다.

## 8. Privacy boundary

Parser 내부는 지원 대상 local artifact를 읽을 수 있다. 그러나 parser boundary 밖으로 나가는 값은 sanitized event draft와 bounded skip reason뿐이다.

다음 surface에는 민감 정보가 절대 나타나면 안 된다.

- SQLite row
- export JSON
- CLI stdout/stderr
- scan_runs warnings/errors
- log/debug output
- doctor output
- TUI view/detail/current-view export
- README fixture/demo output

금지 정보:

- prompt/response 원문
- API key, OAuth token, auth token, credential store 내용
- raw source payload
- raw file path, home path, repo name, private file content
- arbitrary metadata field
- auth/config file content

Metadata는 allowlist 방식으로만 허용한다. 예: parser version, schema variant, safe skip code, hashed provenance, record ordinal hash.

## 9. Parser contract

Parser interface는 다음 책임만 가진다.

- default candidate path 제공
- user path candidate classify
- artifact discover
- artifact parse
- sanitized event draft 반환
- bounded sanitized skip reason 반환

Parser가 하지 않는다.

- DB write
- pricing 계산
- global fingerprint 생성
- raw payload logging
- arbitrary metadata 전달

Scanner가 담당한다.

- Zod validation
- sourceName resolution
- pricing
- central fingerprint
- DB transaction
- scan_runs lifecycle/counts

## 10. Codex parser prototype

Codex MVP는 recognized session/log candidate만 처리한다.

- 기본 후보: `~/.codex/sessions`와 안전하게 allowlist된 session/log files
- broad recursive `~/.codex` crawling 금지
- `auth.json`, OAuth/config/credential/token 관련 파일 denylist
- JSON/JSONL synthetic fixtures를 우선 지원
- token alias: `input_tokens`, `prompt_tokens`, `output_tokens`, `completion_tokens`, `cached_tokens`, `reasoning_tokens`, `total_tokens`
- unknown schema, empty file, bad line, bad timestamp, no token evidence는 전체 scan 실패가 아니라 sanitized skip으로 처리한다.

## 11. OpenCode parser prototype

OpenCode MVP는 recognized JSON/JSONL/SQLite candidate만 처리한다.

SQLite 정책:

- source DB는 read-only로 open한다.
- recognized table/column allowlist만 query한다.
- `SELECT *` 금지
- attach/copy/migration/vacuum/write 금지
- unknown/corrupt/locked schema는 sanitized skip reason으로 처리한다.
- positive SQLite fixture와 unknown schema negative fixture를 반드시 둔다.

기본 후보는 안전한 OpenCode data/log path를 allowlist 방식으로 탐색한다. OpenCode auth/config/credential material은 읽거나 출력하지 않는다.

## 12. Pricing policy

Static pricing table을 사용한다.

- Known model: input/output/cached token cost를 계산한다.
- Unknown model: usage event는 저장하고 `estimatedCostUsd = null`로 둔다.
- Cost는 estimate임을 CLI/TUI/README에 명시한다.
- Pricing version/source를 export manifest와 event metadata 또는 pricing table에 남긴다.
- 실시간 가격 업데이트는 구현하지 않는다.

## 13. Import/export

Export는 TokenWatch JSON manifest만 생성한다.

포함:

- app name/version
- export schema version
- exportedAt
- pricing version/source
- event count
- canonical ordered events

Export에는 `app_config`, `scan_runs`, raw paths, raw errors, raw parser metadata를 포함하지 않는다.

Import 정책:

- TokenWatch export manifest만 허용한다.
- 모든 event는 Zod schema와 metadata allowlist를 다시 통과한다.
- same ID same payload는 duplicate skip으로 count한다.
- same ID different payload는 conflict로 보고하고 overwrite하지 않는다.
- import result는 inserted/duplicate/conflict/rejected count를 출력한다.
- export/import/export equality test에서는 volatile field를 제외하고 canonical ordering을 비교한다.

## 14. CLI command contract

필수 명령:

```bash
tokenwatch --help
tokenwatch scan
tokenwatch scan --source codex
tokenwatch scan --source opencode
tokenwatch scan --path /custom/path
tokenwatch scan --source-name gpu-a100-01
tokenwatch summary
tokenwatch summary --group-by model
tokenwatch summary --group-by agent
tokenwatch summary --group-by source
tokenwatch summary --group-by sourceName
tokenwatch summary --group-by day
tokenwatch summary --group-by hour
tokenwatch summary --json
tokenwatch tui
tokenwatch export --out usage.json
tokenwatch import usage.json
tokenwatch doctor
tokenwatch config get
tokenwatch config set source_name gpu-a100-01
tokenwatch seed
tokenwatch reset --yes
```

Exit/output policy:

- Empty DB summary는 exit 0이다.
- Partial parser skip이 있어도 scan 자체가 완료되면 exit 0과 skip count를 출력한다.
- invalid CLI/import/config, DB open failure, migration failure는 non-zero이다.
- unknown pricing은 non-fatal이다.
- `--json`은 stdout에 valid JSON만 출력하고 warning은 stderr로 보낸다.
- `reset --yes`는 resolved TokenWatch DB에만 작동하고 source artifact는 절대 삭제하지 않는다.
- `config set source_name`은 key allowlist, length cap, printable char validation을 적용한다.

## 15. Doctor command

`doctor`는 privacy-safe diagnostic만 수행한다.

확인 항목:

- OS/Node/pnpm/package version
- `better-sqlite3` load 가능 여부
- DB path와 writeability
- schema version/migration 상태
- usage_events/scan_runs count
- resolved `sourceName`
- parser registry 상태
- default candidate directory 존재/readability 여부
- recent scan_runs summary
- unknown pricing model list

금지:

- auth/OAuth/API key file 읽기
- credential store 접근
- prompt/response/raw payload 출력
- full sensitive path 출력
- provider account validation

Optional source directory 부재는 warning이지 fatal이 아니다.

## 16. TUI contract

`tokenwatch tui`는 Ink 기반 interactive TUI를 실행한다. TUI는 shared query service만 사용하고 독립 aggregation logic을 만들지 않는다.

필수 화면:

- Overview
- By Source
- By Source Name
- By Model
- By Agent
- Daily Usage
- Hourly Usage
- Recent Scan Runs
- Unknown Pricing
- Help

원래 요구된 화면은 모두 포함하고, `sourceName` 화면은 source/server attribution을 위해 추가한다.

필수 keybinding:

- `↑ / ↓`: row 이동
- `← / →`: view/tab 이동
- `Enter`: sanitized detail 보기
- `Space`: MVP에서는 selection/filter toggle로 동작하되, 효과가 제한적이어도 crash 없이 상태를 표시한다.
- `r`: DB re-query refresh
- `e`: 현재 view의 sanitized data export
- `?`: Help
- `q`: 종료
- `Esc`: detail/modal 닫기

TUI detail에는 canonical sanitized metadata만 표시한다. prompt, response, API key, OAuth token, raw path, raw record, private file content는 표시하지 않는다.

Small terminal에서는 column 축소/생략/empty state로 깨지지 않게 한다. Visual polish보다 안정성과 정보 일관성을 우선한다.

## 17. Test fixture policy

테스트는 real user logs를 사용하지 않는다. 모든 fixture는 synthetic이다.

Fixture에는 의도적으로 sentinel secret 문자열을 넣는다.

- fake API key
- fake OAuth token
- prompt text sentinel
- response text sentinel
- repo/path/private content sentinel
- auth/config-like field

테스트는 sentinel이 DB, export, CLI, doctor, scan_runs, TUI render output에 나타나지 않음을 검증한다.
