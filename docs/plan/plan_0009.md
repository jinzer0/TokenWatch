# Plan 0009: Watch / Live Token Velocity Verification Review

## 출처와 대상

- 원본 draft: `docs/draft/draft_0007.md`
- 대상 plan 파일: `docs/plan/plan_0009.md`

- 이 plan은 Round 3까지의 adversarial hyperplan 교정 사항을 반영합니다.
- 이 작업은 최근 구현된 `watch` mode / live token velocity 기능의 검증 및 리뷰입니다. 새 기능 구현 계획이 아닙니다.

## 목표

최근 Watch/live token velocity 작업이 정확하고, 테스트되어 있으며, 필요한 문서와 일치하고, privacy-safe한지 검증합니다.

새 기능을 구현하지 마십시오. 범위를 넓히지 마십시오. 코드, 문서, 테스트 수정은 구현 결함, 테스트 결함, 문서 불일치, privacy 결함이 확인된 뒤에만 허용됩니다. 모든 수정은 확인된 결함을 해결하는 가장 작은 안전한 변경이어야 하며 즉시 검증되어야 합니다.

## 하드 결정 게이트

모든 검증이 통과하면, 요청된 plan 파일과 최종 검증 보고서 외에는 source 변경을 하지 마십시오.

결함이 확인된 경우에만 TDD 지향 micro-remediation을 수행하십시오.

## Phase 4: Isolated Manual Smoke

반드시 isolated DB만 사용하십시오. 실제 user DB 또는 default `~/.tokenwatch/tokenwatch.db`를 사용하지 마십시오.

예시 temp path:

```bash
TOKENWATCH_DB_PATH=/tmp/tokenwatch-watch-verify.db
```

Smoke가 `dist/cli.js`를 사용한다면 먼저 build하십시오.

```bash
corepack pnpm build
```

Static `seed` data는 current-window activity가 필요 없는 basic CLI non-crash/output-shape check에만 사용할 수 있습니다. Nonzero rolling `window`, nonzero `velocity`, filter totals, budget-relevant current activity를 검증하는 smoke는 반드시 isolated DB에 runtime-relative synthetic events, import data, 또는 test-helper-created rows를 사용해야 합니다.

필수 smoke coverage:

| Scenario                        | Required Result                                                                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `watch --once` text             | exit 0, delta/window/velocity/top/budget/privacy concepts 포함, privacy leak 없음                                  |
| `watch --once --json`           | exit 0, stdout이 JSON document 하나로 parse됨, `watchTickReportSchema`로 schema-valid, stderr 없음                 |
| nonzero current-window activity | stale static seed data가 아니라 runtime-relative synthetic event data 사용                                         |
| repeated `--source`             | `filters.source` array에 반영되고 적용됨                                                                           |
| repeated `--source-name`        | `filters.sourceName` array에 반영되고 적용됨                                                                       |
| combined source/sourceName      | 같은 dimension 내 OR, dimension 간 AND                                                                             |
| invalid `--interval`            | nonzero exit, sanitized error, stack trace/raw input leak 없음                                                     |
| invalid `--window`              | nonzero exit, sanitized error, stack trace/raw input leak 없음                                                     |
| no events                       | clean exit, zero totals, 구현된 unknown/default top labels, schema-valid JSON                                      |
| unknown filter result           | clean exit, empty/zero report, crash 없음                                                                          |
| bounded continuous loop         | stdout/stderr를 내부 capture, compact parseable NDJSON lines, SIGINT 또는 controlled termination, stack trace 없음 |
| privacy sentinel scan           | sentinel-bearing synthetic input/temp DB output에 sentinel 없음                                                    |

Manual smoke는 synthetic seed/import/test-helper data만 사용할 수 있습니다. Privacy sentinel checks는 sentinel-bearing synthetic input, fixtures, 또는 temp DB rows를 사용할 때만 의미가 있습니다. 임의의 실제 local agent logs를 scan하지 마십시오.

Final report에 raw stdout/stderr를 붙여넣지 마십시오. Command, exit status, parsed/schema-validation result, 필요한 line count, sanitized observations만 기록하십시오.

## Phase 5: Budget Semantics Review

Watch budget output이 rolling-window budget이 아니라 current-month budget summary인지 검증하십시오.

Acceptance checks:

| Check                    | 기대 결과                              |
| ------------------------ | -------------------------------------- |
| `budgets` scope          | Watch rolling window에서 파생되지 않음 |
| `monthly_total` rows     | month-scoped 유지                      |
| `sourceName` budget rows | sourceName-scoped 유지                 |
| budget status values     | stable and sanitized                   |
| unknown pricing          | applicable한 곳에서 unknown/null 유지  |

Risk note: month-boundary run에서는 Watch `timestamp`, current-month budget evaluation, event timestamps가 서로 다른 clock 또는 time zone을 사용할 경우 consistency bug가 드러날 수 있습니다. Month-boundary inconsistency가 확인되면 fixed/injected clock을 사용하는 focused regression test를 먼저 추가한 뒤 수정하십시오. Budget redesign으로 범위를 넓히지 마십시오.

## Phase 6: Privacy Review

Watch output은 다음을 저장, export, render, report하면 안 됩니다.

- prompts
- responses
- API keys
- OAuth tokens
- credentials
- raw paths
- raw session IDs
- raw records
- SQL payloads
- stack traces
- arbitrary metadata dumps

Privacy checks 대상:

| Surface                  | 조건                                                  |
| ------------------------ | ----------------------------------------------------- |
| text once output         | 항상 확인                                             |
| JSON once output         | 항상 확인                                             |
| continuous NDJSON output | bounded loop에서 확인                                 |
| invalid option errors    | sanitized error 확인                                  |
| tests and snapshots      | 변경된 경우 확인                                      |
| docs examples            | 변경된 경우 확인                                      |
| TUI output               | Watch/Live TUI surface가 변경 또는 구현된 경우만 확인 |

Privacy sentinel scan은 sentinel-bearing synthetic input, fixtures, 또는 temp DB rows를 사용해야 합니다. Reports에는 raw stdout/stderr를 포함하지 마십시오. Leak가 확인되면 blocking defect로 취급하고 중단하십시오. Sentinel regression test를 먼저 추가한 뒤 leaking boundary에서 가장 작은 fix를 적용하십시오.
