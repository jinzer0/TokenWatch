## Contract Gap Gates

### JSON / DTO

- [ ] `kind: "heatmap"`을 유지한다.
- [ ] 기존 `version: 1`이 있으면 안정적으로 유지한다.
- [ ] `year`, `metric`, `filters`, `totals`, `days`, `legend`, `privacy`를 테스트로 고정한다.
- [ ] 숫자는 숫자로 출력한다. Formatted token/currency string은 JSON contract에 넣지 않는다.
- [ ] `days.length`는 non-leap year `365`, leap year `366`이다.
- [ ] `level`은 numeric `0..5`이며 nullable schema로 바꾸지 않는다.
- [ ] `filters.source`와 `filters.sourceName`은 normalized safe field 또는 `null`이다.
- [ ] Privacy object는 기존 contract를 깨지 않는 범위에서 `sanitized: true`와 raw leak false semantics를 명확히 한다.

### 날짜 / Calendar

- [ ] UTC half-open year range를 사용한다: `[YYYY-01-01T00:00:00.000Z, YYYY+1-01-01T00:00:00.000Z)`.
- [ ] Leap/non-leap invariant를 테스트한다.
- [ ] Weekday-based calendar layout alignment를 테스트한다.
- [ ] Year parsing은 invalid year를 명확히 거부한다.

### Metric / Cost

- [ ] `tokens`, `events`, `cost`만 허용한다.
- [ ] Cost metric은 known estimated cost만 합산한다.
- [ ] Unknown estimated cost event는 `unknownCostEvents`에 집계한다.
- [ ] Unknown cost는 zero/free/`$0.00`로 표시하거나 export하지 않는다.
- [ ] Cost metric legend/label은 estimated semantics를 드러낸다.

### Density

- [ ] 정확한 symbol sequence는 `· ▁ ▂ ▃ ▅ █`이다.
- [ ] `0` value는 level `0`.
- [ ] Positive value는 max positive value 대비 `1..5`.
- [ ] All-zero year는 모든 day level `0`.

## DIFFERENCES_SUMMARY

### 수정

- 기존 계획을 greenfield feature-build에서 existing baseline audit + gap remediation 계획으로 수정했다. 이유: Hyperplan team findings에 따르면 TokenWatch에는 이미 heatmap CLI/report/TUI/tests 경로가 존재하므로 새 architecture를 만들면 오히려 회귀 위험이 크다.
- 구현 순서를 “새 서비스/렌더러 생성”이 아니라 “기존 path 확인 -> contract gap test -> 최소 remediation -> 회귀 검증”으로 바꿨다. 이유: 현재 baseline을 보존하고 `draft_0004`와 어긋나는 부분만 닫기 위해서다.
- JSON schema 계획에서 `version: 1` 보존을 명시했다. 이유: 기존 v1 report contract가 있으면 `schemaVersion` rename 같은 불필요한 contract break를 피해야 한다.
- TUI를 optional new work가 아니라 existing Activity Heatmap preservation gate로 수정했다. 이유: 새 navigation이나 mandatory TUI 확장은 scope creep이며, 기존 TUI가 있을 때만 gap을 보완하면 된다.
- Date semantics를 UTC half-open year, `365/366`, weekday alignment로 더 구체화했다. 이유: Hyperplan logic-adversary가 이 부분을 non-negotiable로 지적했다.

### 추가

- Baseline 보존 원칙을 추가했다. 이유: wholesale rewrite, directory move, DB API redesign, migration, index 추가, fixed-point rewrite 같은 과잉 구현을 막기 위해서다.
- Density symbol contract `· ▁ ▂ ▃ ▅ █`를 contract gate로 추가했다. 이유: draft 요구와 기존 구현이 다를 수 있는 핵심 gap이기 때문이다.
- Deterministic same-report renderer output을 추가했다. 이유: JSON/text/SVG/TUI가 각자 계산하면 cross-surface inconsistency가 생긴다.
- Output file boundary와 error behavior task를 추가했다. 이유: invalid extension, output acknowledgement path privacy, parseable JSON, SVG safety가 실제 회귀 위험 지점이다.
- Privacy sentinel expansion task를 추가했다. 이유: CLI, JSON, files, SVG, docs, snapshots, TUI 전체 surface를 한 번에 막아야 한다.
- Atomic commit strategy를 gap remediation 기준으로 추가했다. 이유: test lock, service fix, renderer/CLI fix, privacy, docs, optional TUI를 review 가능한 단위로 나누기 위해서다.

### 삭제/축소

- 새 heatmap architecture 제안을 삭제했다. 이유: 기존 implementation path가 있으므로 새 구조는 불필요하고 위험하다.
- DB migration, index, DB API redesign 요구를 삭제했다. 이유: Hyperplan findings상 evidence 없이 성능/DB 구조를 바꾸면 scope creep이다.
- Fixed-point cost rewrite 요구를 삭제했다. 이유: 이번 계획은 unknown cost semantics와 JSON numeric contract를 지키는 것이 목적이지 cost storage model을 바꾸는 작업이 아니다.

- SVG pixel snapshot, all-OS matrix, 새 TUI navigation을 삭제했다. 이유: 필요한 것은 deterministic renderer contract와 privacy/smoke 검증이지 과도한 visual/system matrix가 아니다.
