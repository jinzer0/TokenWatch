## 목표

TUI Overview를 단순 metric table에서 터미널 안전 KPI dashboard로 개선한다.

Dashboard는 aggregate-only, privacy-safe usage metadata만 표시한다.

| KPI             | 필수 값                                  |
| --------------- | ---------------------------------------- |
| Today           | Tokens, estimated cost                   |
| This Week       | Tokens, estimated cost                   |
| This Month      | Tokens, estimated cost                   |
| Total           | Tokens, estimated cost                   |
| Top source      | total tokens 기준 top `source` label     |
| Top sourceName  | total tokens 기준 top `sourceName` label |
| Top model       | total tokens 기준 top model label        |
| Unknown pricing | unknown pricing event count              |
| Budget          | status, progress summary                 |

`This Month`는 tokens와 estimated cost를 모두 포함해야 한다. Budget percent/status는 This Month가 아니라 Budget KPI에 속한다.

## Product Contract

Overview dashboard는 터미널에서 읽기 쉬운 계층 구조를 제공해야 한다. 정확한 ASCII box art, 고정 decorative borders, emojis, animation, design-system sprawl은 요구하지 않는다.

| 계층      | 내용                                                          |
| --------- | ------------------------------------------------------------- |
| Primary   | Today, This Week, This Month, Budget                          |
| Secondary | Total, Top source, Top sourceName, Top model, Unknown pricing |
| Optional  | Recent activity sparkline, 단 scope-safe한 경우만             |

규칙:

- 모든 KPI는 명확한 label을 가진다.
- Token 값은 token unit을 포함한다.
- Cost 값은 estimated임을 표시한다.
- Unknown pricing count는 반드시 보인다.
- Budget status와 progress는 반드시 보인다.
- Top source, Top sourceName, Top model은 각각 별도 label로 표시한다.
- 최종 UI에서 `Top: source · model · sourceName`처럼 모호한 통합 label을 사용하지 않는다.
- Missing 또는 unknown price는 `unknown`, `null`, 또는 동등하게 명확한 unknown label로 표시한다.
- Missing 또는 unknown price를 `$0.00`, free, zero, no cost로 표시하지 않는다.

## Service-Owned Data Contract

Service-owned sanitized Overview dashboard DTO를 추가하거나 확장한다. 이름은 `overviewDashboard`를 예로 들 수 있지만, 실제 이름은 기존 저장소 convention을 따른다.

DTO는 service/aggregator layer에서 생성한다. Ink rendering component가 계산하지 않는다.

| Field group             | 필수 내용                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------- |
| Period KPIs             | Today, This Week, This Month, Total                                                |
| Period values           | 각 period의 token total과 estimated cost                                           |
| Top labels              | Top source, Top sourceName, Top model                                              |
| Unknown pricing         | Unknown pricing event count                                                        |
| Budget summary          | Budget status, progress, primary budget row selection, other rows의 safe summary   |
| Presentation metadata   | Safe labels, units, estimated marker text, layout-neutral status labels            |
| Primitive compatibility | 기존 `overviewRows` 유지 또는 DTO에서 sanitized primitive `overviewRows`로 mapping |

DTO는 prompt, response, API key, OAuth token, credential, raw local path, raw session ID, raw record, SQL payload, stack trace, arbitrary metadata dump, raw parser/provider payload를 포함하지 않는다.

Ink component는 presentation/layout만 담당한다. Layout mode를 선택하고 DTO 문자열을 렌더링할 수는 있지만, period aggregation, top label calculation, unknown pricing calculation, budget precedence calculation을 수행하지 않는다.

## Budget 규칙

Budget은 `BudgetStatusService` 또는 `budgetStatusRows`를 재사용해야 한다.

구체적인 기존 component가 없고 canonical budget rows를 이미 쓰는 것이 아니라면, 모호한 `BudgetBar` 개념에 의존하지 않는다.

Budget summary precedence:

| 조건                                     | Summary status   |
| ---------------------------------------- | ---------------- |
| Budget row 없음                          | `not_configured` |
| 하나라도 exceeded                        | `exceeded`       |
| exceeded가 없고 unknown row 존재         | `unknown`        |
| exceeded/unknown이 없고 warning row 존재 | `warning`        |
| 그 외                                    | `ok`             |

Budget row selection:

- `monthly_total` row가 있으면 primary budget card로 우선 사용한다.
- 다른 budget row는 private/raw data 없이 안전하게 요약한다.
- Canonical budget row에서 progress를 사용할 수 있으면 표시한다.
- Progress를 안전하게 계산할 수 없으면 값을 만들어내지 말고 명확한 unknown/not configured 상태를 표시한다.
- Budget calculation을 Ink component에서 중복 구현하지 않는다.

## Unknown Pricing 규칙

Unknown pricing은 cost confidence의 일부이며 cost 또는 budget context 근처에 보여야 한다.

필수 동작:

- Overview에 unknown pricing event count를 표시한다.
- Unknown cost value는 `null`/`unknown`으로 유지한다.
- Unknown cost를 `$0.00`으로 변환하지 않는다.
- Unknown cost를 free, zero, no cost처럼 오해되는 문구로 표현하지 않는다.
- Unknown pricing tokens/details는 이미 sanitized aggregate data로 사용 가능하고 유용할 때만 선택적으로 표시한다.
- Period cost summary에 partial unknown pricing이 있을 수 있으므로 estimated cost semantics와 unknown pricing count를 함께 전달한다.

## Responsive Contract

Responsive contract는 deterministic하고 testable해야 한다.

Wide/medium/narrow mode 또는 동등한 layout model을 사용한다. 실제 terminal에 의존하지 않고 compact behavior를 검증할 수 있도록 injectable width/layout seam 또는 deterministic test helper를 제공한다.

| Mode   | Expected layout                                                  | 필수 보존 내용                                                                                                    |
| ------ | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Wide   | Dashboard/card style layout                                      | 모든 primary/secondary KPI, labels, units, estimated markers, budget status/progress, unknown pricing count       |
| Medium | 2x2 primary KPI layout과 secondary rows 같은 condensed dashboard | Today, This Week, This Month, Budget, Total, top labels, unknown pricing                                          |
| Narrow | Labeled rows 또는 동등한 compact fallback                        | Labels, values, units, estimated markers, budget status/progress, unknown pricing count, horizontal overflow 없음 |

Compact fallback 규칙:

- Labels와 values를 보존한다.
- Token units를 보존한다.
- Estimated cost markers를 보존한다.
- Budget status/progress를 보존한다.
- Unknown pricing count를 보존한다.
- Horizontal overflow를 피한다.
- Optional sparkline을 가장 먼저 생략한다.
- Required content를 삭제하기 전에 decoration, borders, spacing을 줄인다.
- Label 없는 value-only row를 렌더링하지 않는다.

README 또는 관련 docs를 업데이트한다. `docs/draft/`는 업데이트하지 않는다.

필수 문서 내용:

- Overview가 KPI dashboard로 렌더링된다.
- Today, This Week, This Month, Total이 token과 estimated cost summary를 보여준다.
- Budget status/progress가 Overview에 표시된다.
- Unknown pricing count가 표시된다.
- Cost는 estimated이며 billing-grade가 아니다.
- Unknown pricing은 unknown/null로 유지되며 `$0.00`이 아니다.
- Overview는 aggregate-only sanitized data를 사용하며 prompt, response, credential, raw path, raw session ID, raw record, SQL payload, stack trace, arbitrary metadata dump를 표시하지 않는다.
- Non-goals: leaderboard, chat, prompt/response analysis, arbitrary credential storage, public social sharing.
- 확장 기능으로 watch mode, heatmap report, cloud sync, tray/menu-bar app, desktop work, 3D graph의 계획상 위치를 명확히 기록한다.
- Sparkline을 추가했거나 제외한 결정.

Acceptance criteria:

- Docs가 실제 구현과 일치한다.
- Docs가 excluded features를 구현된 것처럼 말하지 않는다.
- Docs가 private/raw data를 노출하지 않는다.

### Phase 9: Watch Mode 확장

목적:

- Overview KPI dashboard와 같은 aggregate/privacy contract를 재사용하는 live watch surface를 제공한다.

작업:

- `watch --once`를 deterministic primitive로 유지한다.
- Continuous watch는 polling 기반으로 유지하고 background daemon 또는 filesystem watcher로 확장하지 않는다.
- Watch tick DTO는 `kind`, `version`, timestamp, rolling window, snapshot, delta, velocity, top labels, budget summary, `privacy: { sanitized: true }`를 포함한다.
- Unknown pricing이 포함된 cost delta는 `unknown`/`null`로 유지하고 `$0.00`으로 표시하지 않는다.
- Text output과 JSON output 모두 raw prompt/response/path/session/payload를 노출하지 않는다.

검증:

- Watch service tests와 CLI tests를 추가한다.
- `watch --once --json` smoke는 isolated DB에서 수행한다.
- Continuous watch는 interval parser와 graceful stop path를 테스트한다.

### Phase 10: Heatmap Report 확장

목적:

- UTC day bucket 기반 activity heatmap을 CLI, file output, TUI activity surface가 공유할 수 있게 한다.

작업:

- Metric은 `tokens`, `events`, `cost`로 제한한다.
- JSON/text/SVG output을 지원하고 PNG는 별도 renderer가 안전하게 확인되기 전까지 추가하지 않는다.
- Cost heatmap은 known cost만 합산하고 unknown cost events를 별도 count로 표시한다.
- Heatmap DTO와 renderer는 prompts, responses, credentials, raw paths, raw session IDs, raw records를 포함하지 않는다.

검증:

- Report contract tests, renderer tests, CLI process tests를 추가한다.
- Invalid year, invalid metric, unsupported extension coverage를 포함한다.
- Output file smoke는 임시 경로와 isolated DB를 사용한다.

### Phase 11: Cloud Sync 확장

목적:

- Local-first 원칙을 유지하면서 opt-in aggregate-only sync 가능성을 설계한다.

작업:

- 기본값은 off이며 명시적 opt-in 없이는 네트워크를 사용하지 않는다.
- Sync payload는 sanitized aggregate metadata만 포함한다.
- Prompt, response, API key, OAuth token, credential, raw path, raw session ID, raw record, SQL payload, stack trace, arbitrary metadata dump는 sync payload와 logs에 포함하지 않는다.
- Credential 저장은 이번 계획에서 금지한다. 인증이 필요하면 별도 보안 계획과 사용자 승인 후 다룬다.
- Conflict handling, retry, deletion semantics는 구현 전에 별도 contract test로 고정한다.

검증:

- Offline/default-off tests를 먼저 작성한다.
- Sync payload privacy tests를 추가한다.
- 외부 side effect가 있는 실제 network smoke는 사용자 승인이 있을 때만 수행한다.

### Phase 12: Desktop 및 Tray/Menu-Bar 확장

목적:

- Electron/React desktop preview와 tray/menu-bar surface에서 같은 sanitized DTO를 재사용한다.

작업:

- Desktop 변경 전 `src/desktop/AGENTS.md`를 읽는다.
- Main/preload/IPC는 sanitized DTO만 전달한다.
- Renderer는 prompts, responses, credentials, raw paths, raw session IDs, raw records, SQL payloads, stack traces를 렌더링하지 않는다.
- Tray/menu-bar는 budget status, today/month tokens, unknown pricing count 같은 짧은 aggregate status만 표시한다.
- Tray/menu-bar는 background daemon, OS notification, auto-update와 분리해 별도 opt-in surface로 설계한다.

검증:

- `corepack pnpm test:desktop`를 추가 또는 확장한다.
- Desktop smoke는 `TOKENWATCH_DB_PATH=/tmp/...` isolated DB를 사용한다.
- Captured logs에 preload/native-module/privacy leak이 없는지 확인한다.

### Phase 13: 3D Graph 확장

목적:

- Usage 관계나 시간 축을 3D로 탐색하는 optional visualization을 sanitized aggregate graph data로만 제공한다.

작업:

- 3D graph는 raw events가 아니라 bucketed aggregate nodes/edges만 소비한다.
- Node labels는 sanitized source/sourceName/model/project labels만 사용한다.
- Raw local path, raw session ID, prompt/response, credential, arbitrary metadata는 graph data에 포함하지 않는다.
- Renderer dependency가 필요하면 dependency update는 별도 사용자 승인과 계획을 요구한다.
- 3D graph는 core CLI/TUI Overview completion criteria를 막는 필수 feature가 아니라 별도 phase로 둔다.

검증:

- Graph DTO privacy tests를 작성한다.
- Renderer snapshot은 private data sentinel이 없는지 검증한다.
- Performance budget과 fallback 2D/table output을 정의한다.

### Phase 14: 확장 기능 통합 검증

목적:

- Watch, heatmap, cloud sync, desktop/tray, 3D graph가 서로 다른 surface에서도 같은 privacy/cost semantics를 유지하는지 확인한다.

작업:

- 각 surface의 JSON/text/UI/export payload를 privacy sentinel로 검증한다.
- Unknown pricing은 모든 surface에서 `unknown`/`null`로 유지한다.
- Budget status/progress는 canonical service 결과를 재사용한다.
- 외부 side effect surface는 opt-in/default-off임을 검증한다.

검증:

- `corepack pnpm typecheck`
- `corepack pnpm test`
- `corepack pnpm lint`
- `corepack pnpm build`
- Desktop 변경이 포함되면 `corepack pnpm test:desktop`와 필요 시 `corepack pnpm build:desktop`
