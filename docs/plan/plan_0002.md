# TokenWatch MVP 잔여 차단 항목 수정 계획

> Provenance: hyperplan adversarial review와 plan-agent handoff를 반영한 최종 실행 계약이다. 이 문서는 `docs/plan_0001.md`의 MVP 완료를 막는 잔여 privacy, CLI error, doctor, `scan_runs`, native dependency 검증 문제만 다룬다.

## 1. 목표

다음 순서로 MVP 잔여 차단 항목을 닫는다.

1. DB, CLI, JSON, doctor, scan history, import/export, TUI 전반의 privacy 보장을 유지한다.
2. `sourceName`과 canonical string field를 저장, 가격 계산, fingerprint, 출력 전에 검증한다.
3. `doctor`가 native SQLite load, DB open, migration 실패 상황에서도 privacy-safe degraded JSON을 출력한다.
4. `scan_runs`를 bounded warning/error, reject/error count, `interrupted` status, safe path representation을 가진 v2 계약으로 올린다.
5. machine-local Node/ABI 경험담을 제거하고 portable Node/Corepack/native verification 절차로 대체한다.

## 2. 비목표

이번 계획에서 하지 않는다.

- 새 parser adapter 추가
- billing-grade cost 정확도 개선
- web/dashboard/daemon/cloud sync 기능
- TUI visual redesign
- `docs/tokscale/` 구현 참고, 포팅, 또는 guidance 복사
- package 배포 자동화
- generated, vendor, reference, orchestration path 수정: `dist/`, `node_modules/`, `.sisyphus/`, `docs/tokscale/`
- 유효한 `sourceName` label을 hash, hide, remove 하는 변경
- 실제 ABI mismatch를 개발자 환경에서 강제로 재현하는 gate

Counter 의미는 구현 전체에서 동일해야 한다.

- `parsed`: 검증을 통과해 normalized event가 된 accepted event 수
- `skipped`: token usage가 아니거나 지원하지 않아 정상적으로 건너뛴 record 수
- `rejected`: privacy/validation 정책 때문에 저장하지 않은 unsafe record 수
- `error`: file/parser/import/native/DB phase의 bounded failure count
- `inserted`, `duplicate`, `conflict`: repository insert 결과 그대로

## 4. 구현 단계

### Stage 1. Contract tests and privacy policy

Deliverables:

- field-specific validator를 공유 privacy policy module로 정리한다.
- `sourceName` safe-label validator를 config, scan option, import event, persisted config read/use에 적용한다.
- `agent`, `provider`, `model`, `rawSource`에 canonical privacy deny 정책을 적용한다.
- naive substring deny를 금지한다. 예를 들어 단순히 `token` 포함만으로 reject하지 않는다.
- realistic allow cases와 sentinel/secret/path/private-content negative cases를 fixture/test로 추가한다.

Gate:

- `corepack pnpm test -- tests/usageEvent.test.ts tests/repositoriesExportImport.test.ts tests/scannerParsers.test.ts`
- `corepack pnpm typecheck`

### Stage 2. CLI error boundary and doctor bootstrap

Deliverables:

- 모든 command failure를 하나의 sanitizer로 통과시킨다.
- `TokenWatchError`, Commander/options, Zod/validation, JSON parse, fs, SQLite/native, migration, parser/scan, TUI startup, unknown error를 bounded message/code로 매핑한다.
- raw invalid value를 error message나 success echo에 포함하지 않는다.
- `doctor` command entry path는 `better-sqlite3` load 실패에도 module-load safe해야 한다. DB-native module evaluation, DB-backed container/repository construction, DB open/migration 전에 runtime/native diagnostics와 degraded JSON을 stdout에 출력할 수 있어야 한다.
- `doctor` degraded report의 exit status를 명확히 한다. 예: report 출력 가능하지만 native/DB unavailable이면 non-zero degraded exit, 정상 report는 zero.
- `getPlatformInfo()` 또는 doctor output에서 hostname을 제거한다.
- DB path는 raw/home-relative/repo path가 아니라 category/status 또는 non-identifying basename만 허용한다. basename도 private project name이 될 수 있으면 category/status를 우선한다.

Gate:

- CLI sanitizer unit/integration tests
- native load failure, DB open failure, migration failure simulation에서 stdout JSON parse 성공
- invalid import/config/group-by/source에서 non-zero, no stack, no raw value/path
- `summary --json` 성공 stdout이 JSON만 포함하고 warning/error는 stderr에만 존재
- `corepack pnpm typecheck`

### Stage 3. Parser/import record validation and accounting

Deliverables:

- parser/import record를 pricing, fingerprint, insert 전에 record 단위로 검증한다.
- unsafe canonical field는 record reject로 처리하고, 같은 artifact/import의 safe record는 계속 저장한다.
- structurally invalid import manifest는 전체 import 실패가 가능하지만, otherwise valid manifest 안의 unsafe event는 per-event reject count로 처리한다.
- scanner/importer/result/scan_runs/doctor/TUI가 같은 counter semantics를 사용한다.
- CLI scan/import output은 bounded reject/error count를 보여주되 raw reason/value를 출력하지 않는다.

Gate:

- sensitive `model`, `provider`, `agent`, `rawSource`, `sourceName` fixture scan/import에서 sentinel이 DB/export/CLI/doctor/TUI에 없어야 한다.
- one bad record + one safe record fixture에서 safe record가 저장되어야 한다.
- import duplicate/conflict semantics가 유지되어야 한다.

### Stage 4. `scan_runs` v2 migration and persistence contract

Deliverables:

- `SCHEMA_VERSION`을 올리고 explicit v1 to v2 migration을 구현한다.
- fresh DB와 existing v1 DB 모두 같은 v2 shape가 된다.
- future schema version은 명확히 거부한다.
- v2는 다음을 저장한다.
  - bounded warning code list JSON 또는 equivalent normalized representation
  - `rejected_records`
  - `error_records` 또는 명시적으로 동등한 error count
  - bounded `error_code`
  - status enum: `running`, `completed`, `failed`, `interrupted`
  - non-identifying path representation: `path_kind`, custom-path boolean, 또는 strict `null | [redacted]`
- free-form `error_message` 저장을 중단한다.
- SQLite row 자체가 privacy surface이므로, 기존 v1 `error_message` 값은 migration에서 bounded `error_code`/`null`로 scrub/map한다. UI/export에서 숨기는 것만으로는 부족하다.
- 기존 scanner가 `path`에 `[redacted]`/`null`을 쓰는 점은 유지 가능한 근거다. current raw path leak으로 주장하지 말고, 앞으로 raw path가 불가능하도록 schema/repository contract를 고정한다.
- stale `running` row는 다음 scan/doctor/DB-backed maintenance path에서 `interrupted`와 bounded code로 정리한다. SIGINT 처리는 optional best-effort이며 crash-time write를 약속하지 않는다.

Gate:

- fresh DB migration test
- manually constructed v1 DB upgrade test with unsafe `error_message` scrub assertion
- future schema version rejection test
- scanner warning/rejected/error persistence test
- failed scan stores bounded code only
- doctor/TUI Recent Scan Runs render v2 fields without sentinel/path/raw error

### Stage 5. Environment and native dependency guidance

Deliverables:

- README의 Node/Corepack/native dependency 안내를 portable하게 정리한다.
- machine-local Node version 또는 PATH 경험담을 제거한다.
- project contract는 Node.js `>=20.11`과 Corepack pnpm으로 유지한다.
- Node version 변경 후 `corepack pnpm install` 또는 `corepack pnpm rebuild better-sqlite3`가 필요함을 명시한다.
- native load check는 guarded in-memory open으로 확인한다. require/import만으로 충분하다고 쓰지 않는다.
- 실제 ABI mismatch를 acceptance gate로 요구하지 않는다. failure path는 mock/seam과 doctor degraded test로 검증한다.

Gate:

- README command review
- `corepack pnpm format:check`
- native in-memory open smoke under the active documented Node

## 5. 최종 검증 체크리스트

### Automated checks

```bash

corepack pnpm build
```

### Built CLI smoke with temp DB

최종 acceptance smoke는 source-level dev command가 아니라 edited tree의 built output을 사용한다.

```bash
corepack pnpm build
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js --help
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js seed
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js scan --source codex --path tests/fixtures/codex/sessions.jsonl
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js scan --source opencode --path tests/fixtures/opencode/events.json
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js summary
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js summary --group-by sourceName
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js summary --json
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js export --out /tmp/tokenwatch-plan-0002-export.json
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002-import.db node dist/cli.js import /tmp/tokenwatch-plan-0002-export.json
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js doctor
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js config get
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js config set source_name gpu-a100-01
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002.db node dist/cli.js reset --yes
```

`seed`는 command smoke일 뿐 parser/import privacy evidence로 세지 않는다.

### Negative smoke

각 command는 non-zero와 privacy-safe stderr를 검증한다.

```bash
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002-negative.db node dist/cli.js import /tmp/invalid-tokenwatch-export.json
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002-negative.db node dist/cli.js config set source_name 'PROMPT_SENTINEL_DO_NOT_LEAK'
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002-negative.db node dist/cli.js scan --source codex --source-name '/private/RAW_PATH_SENTINEL_DO_NOT_LEAK' --path tests/fixtures/codex/sessions.jsonl
TOKENWATCH_DB_PATH=/tmp/tokenwatch-plan-0002-negative.db node dist/cli.js summary --group-by invalid
```

Expected:

- non-zero where appropriate
- no stack trace or raw `Error:` dump
- no raw invalid value, raw JSON snippet, home/private path, prompt, response, credential, raw record
- JSON stdout remains parseable for JSON-output commands

### TUI focused QA

- temp DB와 temp cwd를 사용한다.
- Recent Scan Runs가 v2 status/count/warning/error code를 privacy-safe하게 렌더링한다.
- current-view export는 temp cwd에서 생성하거나 cleanup하며 sentinel/path/raw error가 없어야 한다.
- basic navigation, help-rendered key hints, refresh, export, quit이 crash 없이 동작한다.
- TUI navigation code가 바뀌지 않았다면 전체 key matrix를 acceptance blocker로 삼지 않는다.

### Privacy sentinel sweep

검사 대상:

- SQLite `usage_events`, `scan_runs`, config rows
- export/import JSON
- CLI stdout/stderr
- doctor JSON
- TUI render/detail/current-view export
- test snapshots/log-like captured output

금지 대상:

- prompt/response sentinel
- API key/OAuth/auth/credential/secret sentinel
- raw path/home path/repo/private-content marker
- raw records, raw JSON snippets, arbitrary metadata dumps
- free-form parser/native/Zod/SQLite exception messages in persisted or rendered scan history

## 6. Acceptance Criteria

완료 조건은 모두 충족해야 한다.

- `sourceName`은 safe label일 때만 저장/출력되며, unsafe 값은 config persistence와 scan_run creation 전에 raw echo 없이 거부된다.
- `agent`, `provider`, `model`, `rawSource`의 sentinel/private 값은 DB/export/CLI/doctor/TUI에 저장되거나 출력되지 않는다.
- parser/import는 unsafe record를 per-record reject하고 safe record를 계속 저장한다.
- CLI failure는 bounded message/code만 출력하고 stack, raw value, raw path, raw JSON을 출력하지 않는다.
- `doctor`는 native load, DB open, migration failure에서도 syntactically valid degraded JSON을 출력한다.
- `scan_runs` v2는 bounded warnings/errors/reject counts/status/path representation을 저장하고, v1 free-form `error_message`를 DB layer에서 scrub/map한다.
- stale `running` row는 다음 scan/doctor/DB-backed maintenance에서 `interrupted`로 정리된다.
- hostname과 machine-local Node/PATH anecdote가 문서와 doctor output에서 제거된다.
- final checks와 built CLI smoke가 temp DB로 통과한다.
- default user DB와 real user logs는 검증 중 건드리지 않는다.
