### Duration Semantics

- `intervalMs` means polling cadence.
- `intervalMs` defaults to `5s`.
- `intervalMs` accepts integer milliseconds, `s`, and `m`.
- `intervalMs` minimum is `5_000`.
- `windowMs` means rolling activity and velocity window.
- `windowMs` defaults to `10m`.
- `windowMs` accepts integer milliseconds, `s`, and `m`.
- `windowMs` must be a positive integer duration.
- `--once` validates `--interval` if supplied but does not wait.
- Invalid duration values fail with bounded sanitized `invalid_report_option` output.

### Tick Semantics

- `--once` computes current rolling window activity over `(now - windowMs, now]`.
- First continuous tick is the same as `--once`.
- Later continuous ticks compute `delta` from event timestamps in `(previousTickAt, now]`.
- Later continuous ticks compute `window` and `velocity` from `(now - windowMs, now]`.
- Top labels come from the rolling `window`, not the prior-tick `delta`.
- Delta is timestamp-based, not ingestion-order-based.
- Late/backfilled rows inserted after a tick with timestamps at or before `previousTickAt` do not appear in later `delta`.
- Late/backfilled rows still affect later `window`, `velocity`, and `top` while their timestamps remain inside `(now - windowMs, now]`.

### JSON Contract

Bump watch JSON to `version: 2`.

Required v2 shape:

- `version: 2`
- `kind: "watch_tick"`
- `timestamp`
- `intervalMs`
- `windowMs`
- `filters: { source: string[], sourceName: string[] }`
- `delta`
- `window`
- `velocity`
- `top`
- `budgets`
- `privacy: { sanitized: true }`

Rules:

- `delta` is prior-tick activity, except `--once` and first continuous tick where it equals current rolling window activity.
- `window` is rolling activity over `(now - windowMs, now]`.
- `velocity` is computed from `window`.
- Numeric fields stay numbers.
- Formatted strings appear only in text output.
- `filters.source` and `filters.sourceName` are arrays, even when empty or single-valued.
- Repeated filters are OR within one field.
- `source` and `sourceName` combine with AND.
- Keep `privacy: { sanitized: true }`; do not use four privacy booleans.
- Reject stale v1-only or draft-only shapes in contract tests when parsed as v2.

### Unknown Cost Semantics

- Never render unknown cost as `$0.00`, free, or zero.
- If any event in `delta` has unknown cost, `delta.estimatedCostUsd` is `null`.
- If any event in `window` has unknown cost, `window.estimatedCostUsd` is `null`.
- If any event in `window` has unknown cost, `velocity.estimatedCostUsdPerHour` is `null`.
- Keep `unknownCostEvents` and `unknownCostTokens` on both `delta` and `window`.
- Add `velocity.unknownCostEvents` and `velocity.unknownCostTokens` only if it avoids renderer ambiguity; otherwise renderers must read them from `window`.
- Do not introduce a known-cost floor field in this remediation unless tests prove it is necessary.

### Budget Semantics

- Reuse canonical current-month budget evaluation.
- Budget status is not per-window.
- Monthly total budget rows remain included.
- `sourceName` budget rows may be filtered by selected `sourceName`, matching existing behavior.
- Budget output must remain sanitized and must not expose raw DB details or raw errors.

### Continuous JSON Stream

- `watch --json` in continuous mode emits NDJSON.
- Each tick is one compact JSON object on one line.
- Each line is independently parseable.
- Do not pretty-print continuous JSON.
- Do not wrap continuous JSON in an array.
- `watch --once --json` emits one parseable JSON document and exits.

### Implementation Shape

- Keep CLI thin.
- Keep business logic in services.
- Refactor watch calculation into pure testable functions with injectable `now`.
- Track prior tick state only in the loop runner or a small service-owned state object.
- Do not persist watch state in the DB.
- Let text and JSON renderers consume one canonical DTO.
- Avoid duplicated calculations between renderers.
- Keep existing `listAll()` polling initially.
- Record `O(total rows)` risk, but do not optimize without evidence.
- Add repository queries or indexes only if profiling or tests prove `listAll()` is a real blocker.

## Per-Defect TDD Repair Loop

For each defect:

1. Reproduce with the smallest focused test or command.
2. Classify the defect.
3. Add or strengthen the failing regression test first.
4. Make the minimal fix.
5. Rerun the narrow test.
6. Rerun adjacent affected tests.
7. Rerun manual QA cases affected by the fix.
8. Rerun broad gates when implementation is complete.
9. Record evidence.
10. Do not batch unrelated fixes.

If a defect appears to require DB migration, index redesign, dependency addition, renderer rewrite, desktop work, or TUI work:

1. Stop.
2. Document why the smaller fix is insufficient.
3. Proceed only if it is the minimal safe remediation for an in-scope defect.

  - 이유: draft 예시가 TokenWatch의 strict schema/privacy convention과 충돌할 수 있기 때문이다.

### 수정

- `--interval` 의미를 refresh/window 겸용에서 polling cadence only로 바꿨다.
  - 이유: draft가 refresh cadence와 velocity window의 분리를 요구하기 때문이다.
- `--window`를 선택 아이디어가 아니라 mandatory implementation target으로 바꿨다.
  - 이유: 현재 watch 구현의 핵심 semantic gap이기 때문이다.
- loop behavior를 rolling-window-only delta에서 prior-tick timestamp delta plus rolling window velocity로 바꿨다.
  - 이유: draft의 “직전 tick 대비 delta”와 “최근 window velocity”를 동시에 만족하기 위해서다.
- top activity 기준을 delta에서 rolling window로 바꿨다.
  - 이유: 아주 작은 tick delta 기준 top은 쉽게 깜박이고 current activity를 왜곡하기 때문이다.
- budget interpretation을 current-month canonical summary로 명확히 했다.
  - 이유: budget threshold는 watch window spend가 아니라 월별 상태 평가이기 때문이다.
- draft privacy booleans를 `privacy: { sanitized: true }`로 바꿨다.
  - 이유: TokenWatch의 strict report convention과 맞추기 위해서다.
- unknown-cost guidance를 known-only rate 출력에서 nullable full cost/rate로 바꿨다.
  - 이유: known-only rate를 total spend로 오해할 수 있기 때문이다.
- TUI guidance를 optional implementation에서 explicit non-goal로 바꿨다.
  - 이유: TUI view는 navigation/help/export/state/test surface를 크게 확장해 이번 PR 범위를 넘기 때문이다.
- verification을 broad command 중심에서 targeted tests first plus broad gates로 바꿨다.
  - 이유: semantic contract regression은 full suite 전에 좁은 테스트로 먼저 증명해야 하기 때문이다.
